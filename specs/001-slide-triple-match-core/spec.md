## User Scenarios & Testing *(mandatory)*

### User Story 1 - 基础滑块三消核心循环（Priority: P1）

作为一名休闲游戏玩家，我在 9:16 竖屏的 H5 页面中看到一张 N×N 棋盘（随关卡从 4×4 扩展至 8×8），棋盘上分布着带花色图案与方向箭头的滑块。我点击某个滑块：若其箭头所指的射线方向上直到棋盘边缘没有任何阻挡，它就滑出棋盘、飞入**顶部**7 格收集槽（Δ19：待消槽由屏幕底部移至棋盘上方，FR-047 §3）；若前方有其他滑块或障碍，它前冲一小段、碰撞并弹回原位（播放震动与受阻音效），高阶关卡中受阻会扣减生命值或步数。飞入收集槽的滑块与同花色滑块自动归拢；凑齐 3 个同花色即触发三消合并动效、腾出 3 个槽位并累加连击（Combo）计分。当我把棋盘上所有滑块全部移入收集槽并三消清空，即胜利。（Δ19：棋盘布局改用奇偶层半格错位堆叠与图形掩码成型，被上层压住的下层滑块变暗且不可点，详见 US7 / FR-044 / FR-045。）

**Why this priority**: 这是游戏唯一的核心循环，是全部 72 关（Δ16 扩容后）与四大机制的承载基底。没有它，其余一切均无意义；单独实现它即构成可玩 MVP。

**Independent Test**: 可通过"第 1 章任意关卡（如 Level 1）完整通关一次"独立测试——点击滑块 → 观察飞出/受阻弹回 → 观察槽内归拢与三消 → 槽满判负或清空棋盘判胜。

**Acceptance Scenarios**:

1. **Given** 4×4 棋盘上某滑块箭头方向射线畅通，**When** 玩家点击该滑块，**Then** 滑块沿箭头滑出棋盘并飞入收集槽，槽内同花色滑块相邻归拢排列。
2. **Given** 某滑块箭头方向前方存在其他滑块或障碍，**When** 玩家点击该滑块，**Then** 滑块前冲碰撞后弹回原位，播放震动与受阻音效，不进入收集槽。
3. **Given** 收集槽内已有 2 个同花色滑块，**When** 第 3 个同花色滑块飞入，**Then** 立即触发三消合并动效，3 个槽位被腾空，连击计数增加。
4. **Given** 棋盘上所有滑块均已飞出且收集槽已三消清空，**When** 最后一次三消动画结束，**Then** 判定胜利并展示通关结算。
5. **Given** 收集槽 7 格已满且未触发三消，**When** 系统判定爆槽，**Then** 判定失败（爆槽死局）。生命值扣完（生命默认 3 点）、或棋盘陷入环形互锁死局（所有剩余滑块前方均被彼此阻挡）时同样判定失败。

### User Story 2 - 72 关递进关卡系统与可解性保证（Priority: P1）

作为玩家/评委，我从 Level 1 开始游玩，随进度经历 3 个 24 关大阶段、难度参数严格递进的 72 关（Δ11 大棋盘波浪架构 + Δ13 增量扩容拼接 + Δ16 尾部扩容至 72 关）：Level 1 固定 5×5 新手引导关（底层满铺 + 局部 2 层堆叠，27~30 块）；Level 2 固定 6×6 进阶过渡关（42~45 块）；Level 3 为新手循环 1 的困难关（7×7、底层满铺 + 局部 2~3 层堆叠、54~60 块、无机关）；Level 4~72 全部采用 7×7 / 8×8 大棋盘，按 3 关一循环的「2 简 1 难」波浪递进（每 2 个 7×7 相对简单爽快关 + 紧跟 1 个 8×8 困难挑战关：L4=7×7简, L5=7×7简, L6=8×8难……直至 L72=8×8，挑战位 = (id-4)%3==2，即 L6/L9/…/L51/L54/L57/L60/L63/L66/L69/L72 共 22 个 8×8 + 44 个 7×7）。花色 3~8 种（7×7 简单关较低、8×8 挑战关较高、最高 8 种），滑块总数从 30 增至 105（恒为 3 的倍数）：前期 L4~16 堆叠 2~3 层（7×7 约 54~63 块、8×8 约 69~78 块），中期 L17~36 堆叠 3~4 层（7×7 约 63~75 块、8×8 约 78~90 块），后期 L37~72 最高堆叠 5 层 z=0..4（7×7 约 72~84 块、8×8 困难关 87~105 块），并逐关解锁四大机制（L7 起齿轮、L12 起冰封、L22 起钥匙锁链、L32 起棱镜，随章节依次解锁并复合；Δ13: 原 L6/L11/L21/L31 档位随 50→60 拼接 +1 平移；Δ16: L61~L72 沿用后期档位参数，不引入新机制）。总体难度随关卡编号 L1→L72 稳步提高（覆盖局部波浪）。每一关都由逆向生成算法离线构建或经自动求解器验证，保证在 7 格槽位限制下 100% 存在至少一条必胜路径；每关附带量化难度指标（最优解步数、解路径数、槽位压力峰值、启用机制数）。（Δ13 拼接铁律：原 50 关的滑块布局与预计算解 100% 原封不动保留复用；Δ16 扩容铁律：**既有 L1~L60 的 tiles/prisms/cfg/solutionMoves 100% 原封不动保留复用**，仅由 tools/expand-60.js 增量生成 L61~L72 共 12 关尾部新关卡，经 Generator 三重验证 + Solver 门禁 + 内嵌 solutionMoves，严禁全量重生成。）（Δ15 修订：为满足 FR-029（Δ15）同花色空间打散约束，既有 60 关允许经"花色重打散 + Solver 全量重验证"流程调整同花色落位——按三档聚散度曲线（L1~L6 / L7~L21 / L22~L60）空间打散、消除"三连排排坐"；网格尺寸、滑块总数、堆叠与机制等结构性参数不变，100% 可解门禁与开放花色数 ≤5 不降级。）

**Why this priority**: "72 关难度递进设计"是本项目两大核心价值轴之一，也是大赛评审核心。关卡系统与核心循环共同构成不可削减的 P1 基底。

**Independent Test**: 可独立测试——逐关加载关卡配置渲染棋盘并按难度参数矩阵核对网格尺寸/花色数/滑块数/机制引入档位；运行求解器对 72 关逐一验证可解性并核对难度指标。

**Acceptance Scenarios**:

1. **Given** 关卡 N ∈ [1,72]，**When** 加载该关，**Then** 其网格尺寸（L1=5×5、L2=6×6、L3=7×7、L4~72 按 7/7/8 三关一循环）、花色种类数、滑块总数（3 的倍数）、堆叠层数与启用机制集合符合阶段参数矩阵。
2. **Given** 任意一关的初始局面，**When** 运行自动求解器回溯验证，**Then** 求解器输出至少一条必胜路径及量化难度指标（最优解步数、解路径数、槽位压力峰值、启用机制数）。
3. **Given** 玩家完成第 N 关，**When** 结算结束，**Then** 返回主大厅且主按钮指向第 N+1 关（第 72 关通关进入全通关庆祝终局）。

### User Story 3 - 四大微创新机制（Priority: P2）

作为进入中高章节的玩家，我在基础方向阻挡之上遭遇四种递增机制并学会利用它们：

- **机制 B 冰封滑块（L11+）**：被冰块包裹的滑块即使前方畅通也无法直接点击飞出，但可作为障碍物阻挡他人；每当收集槽成功触发 1 次三消，场上所有冰封滑块冰层厚度减 1，归零破冰变为普通滑块。
- **机制 C 钥匙与锁链（L21+）**：部分滑块被锁链锁在原地，需先让带【钥匙角标】的特定滑块飞出棋盘，才能自动解开对应锁链。

**Independent Test**: 可分别在启用单一机制的章节关卡（L6+、L11+、L21+、L31+）独立测试每个机制的触发、反馈与机制间交互。

**Acceptance Scenarios**:

6. **Given** L31+ 某关中滑块箭头指向棱镜块，**When** 玩家点击该滑块，**Then** 滑块不被弹回，而是折射 90° 从棱镜另一侧飞出棋盘并进入收集槽。
7. **Given** 第 4 章（L31-40）某关，**When** 加载，**Then** 棱镜与冰封、齿轮机制混排出现，机制间交互（如破冰依赖三消、齿轮随飞出转向）均按各自规则正确联动。

### User Story 7 - 奇偶层半格错位玩法、前两关教学、顶部待消槽与 IQ 指数、三大道具与白瓷碎裂视听（Priority: P1）

作为玩家，我在第 1 关开局看到一张简洁美观的引导卡片与动态手指指引，学会「点击前方无阻挡的卡牌，使其沿箭头滑入上方待消槽，集齐 3 张相同卡牌即可碎裂消除」；在第 2 关开局再学会「深色卡牌被上层压住无法移动，必须先消去压在它上面的亮色上层卡牌才能解锁下层；不同层之间的飞行路线互不干扰」，此后不再被打扰。开局后我发现棋盘不再是一块死板的正方格阵——奇数层的卡牌向右下偏移半格、严丝合缝地压在下层四格的十字交界上；被压住的下层卡牌自动变暗且点不动，必须先拆掉压住它的上层卡牌；每关底层与上层都按可辨识的图形轮廓（蝴蝶、爱心、双岛、拱桥、金字塔、钥匙孔、十字礼盒、沙漏、风车、皇冠、四叶草、六芒星、螺旋、蜂巢等 36 套掩码）成型，而不再是千篇一律的正方形满铺。局内顶部改为一排控件：左上角并排【↩ 返回大厅】与【⚙️ 设置】两个圆形立体按钮、正中央只显示 `关卡 X`、右上角显示【💎 棱晶数量】；顶栏正下方的 IQ 指数条从 `IQ: 90` 起步，每触发一次三消就跳字递增并推进我的趣味头衔；再下方是厚重立体的 7 格待消槽托盘——它从屏幕底部搬到了棋盘正上方，我在那里就能看清自己的收集进度。底部道具栏则是三枚原创大圆按钮：撤销回滚上一步；「灵犀三消」无视方向阻挡与层叠锁定，直接从全场凑齐 3 张同花色吸入待消槽完成一次碎裂；「乾坤洗牌」把场上剩余卡牌的花色与方向全部重排且保证洗牌后仍 100% 可通关。每当 3 张同花色卡牌在待消槽触发消除，槽位处会爆裂迸发出数十枚带高光与阴影面片的白瓷多边形碎片向四周抛射翻滚、随重力飘落消散，同时响起一声清爽通透的薄瓷碎裂脆响。

**Why this priority**: US7 是"核心玩法手感与局内可读性"的承载层——半格错位堆叠与压制锁定把基础三消从"平面消消"升级为"空间拆解"（直接强化「玩法融合微创新」价值轴），前两关教学保证上手门槛，顶部待消槽与 IQ 指数建立局内信息层级，三大道具提供容错与破局手段，白瓷碎裂视听提供品质感反馈。其中**半格错位堆叠与图形掩码会改写棋盘布局与关卡生成契约**，属核心玩法本体而非装饰层，故与 US1/US2 同列 P1；教学卡片、IQ 头衔与碎裂特效为体验增强（不改变规则语义），但因与 FR-044/FR-045 强耦合实现，故整条随本体同优先级交付。

**Independent Test**: 可独立测试——第 1 关验证引导卡片与手指指引可跳过且教学语义准确；第 2 关验证层叠压制引导可跳过、第 3 关起零新手提示；逐关核对奇数层半格偏移坐标、零悬空约束、被压滑块变暗且不可点、同层射线阻挡与跨层互不干扰；逐关核对底层与上层成型于 36 套掩码轮廓之一；局内核对顶栏三区布局与 `关卡 X` 无 `/72` 后缀、IQ 条初值 90 与三消递增/受阻归零 combo、7 格待消槽位于棋盘上方；道具栏核对撤销回滚完整性、灵犀三消无视阻挡取最顶层同花色、洗牌后必胜可解；每次三消核对 45~60 枚白瓷多边形碎片爆裂与清脆碎裂音效触发。

**Acceptance Scenarios**:

1. **Given** 第 1 关开局，**When** 玩家首次进入，**Then** 屏幕展示玩法引导卡片与动态手指指引（指向一个前方无阻挡的可飞出行卡牌），说明「点击前方无阻挡的卡牌使其沿箭头滑入上方待消槽，集齐 3 张相同卡牌即可碎裂消除」；玩家可随时点击跳过，引导不阻塞棋盘输入。
2. **Given** 第 2 关开局，**When** 玩家首次进入，**Then** 屏幕展示层叠压制引导，说明「深色卡牌被上层压住无法移动，必须先消去压在它上面的亮色上层卡牌才能解锁下层；不同层之间的飞行路线互不干扰」；玩家可随时点击跳过。
3. **Given** 任意关卡 N ≥ 3，**When** 玩家进入该关，**Then** 不再弹出任何新手提示或教学卡片。
4. **Given** 棋盘存在奇数层（`z = 1, 3`）与偶数层（`z = 0, 2, 4`）滑块，**When** 渲染与命中判定执行，**Then** 偶数层位于标准网格 `(r, c)`、奇数层位于 `(r + 0.5, c + 0.5)`；同层相邻滑块紧凑贴合（间距 1px），方向箭头内嵌于滑块圆角边缘内侧且不被邻牌遮挡。

### Edge Cases

- **收集槽满但可三消**：第 7 格被占的同一点击内若恰好凑成第三同花色（满槽时飞入即三消），系统须判三消优先于爆槽——先消除再判负，玩家不因满槽瞬态被误判失败。
- **同一点击内连环触发**：一次飞出可能同时触发齿轮旋转→另一滑块解锁路径、三消→全场破冰等多重级联；所有级联须在一个原子回合内按确定顺序结算完毕，Undo 须能整体回滚。
- **互锁死局检测误报**：普通玩家可能尚未发现隐藏解（如先让某滑块受阻弹回以触发齿轮/利用道具）；死局判定须仅在实际无任何合法操作或道具无法挽救时触发，且基于求解器口径或穷举口径判定，避免误杀。
- **零滑块/空棋盘边界**：关卡生成必须保证初始滑块数 ≥1 且恒为 3 的倍数；三消后棋盘与槽同时清空即判胜，不出现"棋盘空但槽残留"的中间态（生成器须保证不存在该态，见 FR-029）。
- **收集槽花色种类溢出**：8 花色第 5 章，7 格槽中理论可同时滞留多于槽位数种未成三组的花色残片；生成器须保证在最优路径上任何时刻未完成三消的"开放花色数"不超过 5（7 格留余量），否则爆槽风险结构性偏高（见 FR-011 难度指标与 FR-030 验证门禁）。
- **锁链滑块作为阻挡**：被锁链锁定的滑块在解锁前同样阻挡射线；生成器须保证钥匙滑块在解锁前自身可达（其前方射线不被永远无法移除的锁链滑块堵死，见 FR-019）。
- **棱镜链**：滑块折射后从另一侧飞出棋盘须终止折射过程，不允许棱镜 A → 棱镜 B 的多重折射（FR-022 上限一次折射）；若关卡数据出现双棱镜对射布局，Generator 必须拒绝。
- **暂存区（已移除）**：原「移出槽位」道具与暂存区功能已整体删除（Δ9——试玩发现点击暂存滑块触发滑块复制分身破坏花色守恒的严重 Bug，且双排空槽视觉冗余）；道具仅剩 Undo 与 Wrench 两种。
- **受阻扣命的边界**：受阻扣减生命值/步数仅限挑战型高阶关卡（第 3 章起启用）；第 1、2 章受阻不扣命，避免新手挫败（FR-003 的分档规则）。
- **旋转方向歧义**：PRD 机制 A 曾同时描述"格子转向垫"与"齿轮标记滑块自动转向"两种载体；spec 统一收敛为齿轮滑块单一载体（Δ1 增量，地面转向垫取消），方向为顺时针 90°、触发口径为"十字相邻滑块飞出"（FR-013/FR-014）。
- **破冰时机歧义**：PRD 机制 B 给出"三消时全场冰层 -1（或十字相邻有滑块飞出时破冰）"两种可选口径；spec 统一主口径为"三消时全场冰层 -1"，十字相邻口径作为关卡数据可配置的变体（FR-016）。
- **图鉴抽样与既有花色数区间冲突（Δ14 关键消解）**：US5 要求单关抽样 6~22 种（分阶段递增），而 FR-008 既有口径为花色 3~8（爆槽风险结构性上限）且 Δ13 铁律要求原 50 关 tiles 100% 原封不动保留——重抽样会改写既有关卡数据的 suit 字段。冲突消解（FR-033 §3）：**图鉴池扩展不改写关卡数据 suit 值**；前端渲染层按阶段映射表将关卡内实际花色数 K（保持 3~8 不变）映射到该阶段图鉴池中的 K 个确定图案（确定性抽样、seed 可复现）；"45 种图鉴"为渐进解锁展示池（收集面板语义），非单关实际花色数上限。
- **阶段边界换装（Δ14，边界经 Δ16 重划）**：换章时图鉴池切换，同花色编号在两阶段映射到不同图案；切换 MUST 仅在换章边界发生（进度推进/跳关/Undo 均以当前关 id 计算阶段，不出现混合阶段图案）。Δ16 将边界重划为 L24→L25（阶段一→二）与 L48→L49（阶段二→三）。

**核心玩法布局与关卡生成（US7/FR-044~FR-045）**

- **FR-044**: 系统 MUST 采用**奇偶层半格错位堆叠 + 零缝隙紧凑拼合**的棋盘布局（Odd/Even Layer Half-Grid Offset & Tight Packing），并在层间引入**压制锁定与自动变暗**语义：
  1. **零缝隙紧凑排布**：同层相邻滑块 MUST 采用紧凑贴合排布（间距 `gap = 1px`）；方向箭头 MUST 内嵌于滑块圆角边缘内侧，MUST NOT 被邻牌遮挡。
  2. **奇偶层半格交错坐标**：偶数层（`z = 0, 2, 4`）MUST 位于标准网格 `(r, c)`；奇数层（`z = 1, 3`）MUST 向右下偏移半格、位于 `(r + 0.5, c + 0.5)`——即恰好压在下层 `2×2` 四个格子的十字交界中心。
  3. **严格防悬空约束（No Floating Tiles）**：任何 `z > 0` 层的滑块，其正下方对应的 `z - 1` 层支撑象限中 MUST 存在有效滑块；严禁滑块悬空出现在空白背景上方。Generator MUST 拒绝违反该约束的候选。
  4. **压制锁定与自动变暗（Overlap Lock & Depth Dimming）**：若某滑块上方 `z + 1` 层的压角位存在任何未移除的滑块，则该下层滑块处于**被压锁定态**——MUST 不可点击，且牌面 MUST 渲染 32% 深色变暗遮罩；仅当压住它的**所有**上层滑块全部移除后，该滑块才恢复 100% 亮白并解锁点击。
  5. **同层独立射线阻挡**：滑块沿方向箭头飞出时，MUST 仅受**同一层 `z`** 前方滑块（及贯穿全层的棱镜）阻挡；不同层级的飞行路线 MUST 互不干扰。
  6. **纯布局层约束**：本条为**棋盘布局与判定本体**变更，MUST 与 FR-001 修订、FR-008 Δ19 全量受控迁移条款、FR-029 §7 半格坐标下的邻接定义修订保持口径一致；命中判定、越界判定与压角位对应关系的精确口径见 Edge Cases 对应条款。
- **FR-045**: 系统 MUST 以内置 **36 套高辨识度图形掩码模板（Shape Masks）** 作为关卡成型方式，MUST NOT 回退到死板的「底层 100% 正方形满铺」旧规：
  1. **掩码库**：每关的底层与上层 MUST 均按图形轮廓成型，掩码模板库 MUST 包含 36 套高辨识度轮廓（蝴蝶、爱心、双岛、拱桥、金字塔、钥匙孔、十字礼盒、沙漏、风车、皇冠、四叶草、六芒星、螺旋、蜂巢等）；模板 id MUST 记录于关卡 `cfg`（随迁移与生成产物落库），MUST NOT 在运行时随机选取。
  2. **层数演进**：L1 MUST 为 1 层；L2 MUST 为 2 层；L3 起 MUST 按 `2-2-3`、`2-3-4` 随进度逐步提升至普遍 3 层以上——`7×7` 简单关最高 4 层，`8×8` 困难关最高 5 层。
  3. **瓶颈卡点算法（Bottleneck Pacing）**：逆向生成时 MUST 构建「窄可行域咽喉点 → 解锁破局 → 连锁爽消 → 下一咽喉点」的依赖链节奏——即每个咽喉点处玩家的合法可行操作集 MUST 被收窄至极少（形成"单线咽喉点"），破局后 MUST 释放连锁爽消的畅快段，再收窄至下一咽喉点。
  4. **可解性铁律**：经 Solver 验证 MUST 达 72/72 关 100% 必胜可解（FR-010/FR-030/FR-031 口径不变），瓶颈节奏 MUST NOT 以牺牲可解性为代价（与 FR-029 §5 可解性不降级铁律并列）。
  5. **纯生成层约束**：本条为**关卡生成契约**变更，MUST 与 FR-008 Δ19 全量受控迁移条款（层数矩阵受控修订）、FR-029 §8 打散与瓶颈节奏的耦合条款保持口径一致；具体掩码几何（每套模板的格点集合定义）由 plan 阶段固化于生成器常量表，spec 只锁定"36 套 / 轮廓成型 / 层数矩阵 / 瓶颈节奏 / 72/72 可解"五条。

### Key Entities *(include if feature involves data)*

- **Level（关卡）**：72 关静态配置实体（Δ13 扩容 60 关，Δ16 再扩容至 72 关）。属性：编号、章节、网格尺寸 N、花色数 K、滑块清单（位置/花色/方向/初始机制标记）、机关格清单（棱镜）、全局参数（生命值默认 3、道具次数、破冰口径、扣命规则）、难度指标（最优解步数、解路径数、槽位压力峰值、启用机制数、难度评估分）、机制标签。
