## User Scenarios & Testing *(mandatory)*

### User Story 1 - 基础滑块三消核心循环（Priority: P1）

作为一名休闲游戏玩家，我在 9:16 竖屏的 H5 页面中看到一张 N×N 棋盘（随关卡从 4×4 扩展至 8×8），棋盘上分布着带花色图案与方向箭头的滑块。我点击某个滑块：若其箭头所指的射线方向上直到棋盘边缘没有任何阻挡，它就滑出棋盘、飞入底部 7 格收集槽；若前方有其他滑块或障碍，它前冲一小段、碰撞并弹回原位（播放震动与受阻音效），高阶关卡中受阻会扣减生命值或步数。飞入收集槽的滑块与同花色滑块自动归拢；凑齐 3 个同花色即触发三消合并动效、腾出 3 个槽位并累加连击（Combo）计分。当我把棋盘上所有滑块全部移入收集槽并三消清空，即胜利。

**Why this priority**: 这是游戏唯一的核心循环，是全部 60 关（Δ13 扩容后）与四大机制的承载基底。没有它，其余一切均无意义；单独实现它即构成可玩 MVP。

**Independent Test**: 可通过"第 1 章任意关卡（如 Level 1）完整通关一次"独立测试——点击滑块 → 观察飞出/受阻弹回 → 观察槽内归拢与三消 → 槽满判负或清空棋盘判胜。

**Acceptance Scenarios**:

1. **Given** 4×4 棋盘上某滑块箭头方向射线畅通，**When** 玩家点击该滑块，**Then** 滑块沿箭头滑出棋盘并飞入收集槽，槽内同花色滑块相邻归拢排列。
2. **Given** 某滑块箭头方向前方存在其他滑块或障碍，**When** 玩家点击该滑块，**Then** 滑块前冲碰撞后弹回原位，播放震动与受阻音效，不进入收集槽。
3. **Given** 收集槽内已有 2 个同花色滑块，**When** 第 3 个同花色滑块飞入，**Then** 立即触发三消合并动效，3 个槽位被腾空，连击计数增加。
4. **Given** 棋盘上所有滑块均已飞出且收集槽已三消清空，**When** 最后一次三消动画结束，**Then** 判定胜利并展示通关结算。
5. **Given** 收集槽 7 格已满且未触发三消，**When** 系统判定爆槽，**Then** 判定失败（爆槽死局）。生命值扣完（生命默认 3 点）、或棋盘陷入环形互锁死局（所有剩余滑块前方均被彼此阻挡）时同样判定失败。

### User Story 2 - 60 关递进关卡系统与可解性保证（Priority: P1）

作为玩家/评委，我从 Level 1 开始游玩，随进度经历 3 个 20 关大阶段、难度参数严格递进的 60 关（Δ11 大棋盘波浪架构 + Δ13 增量扩容拼接）：Level 1 固定 5×5 新手引导关（底层满铺 + 局部 2 层堆叠，27~30 块）；Level 2 固定 6×6 进阶过渡关（42~45 块）；Level 3 为新手循环 1 的困难关（7×7、底层满铺 + 局部 2~3 层堆叠、54~60 块、无机关）；Level 4~60 全部采用 7×7 / 8×8 大棋盘，按 3 关一循环的「2 简 1 难」波浪递进（每 2 个 7×7 相对简单爽快关 + 紧跟 1 个 8×8 困难挑战关：L4=7×7简, L5=7×7简, L6=8×8难……直至 L60=8×8，挑战位 = (id-4)%3==2，即 L6/L9/…/L51/L54/L57/L60 共 19 个 8×8 + 38 个 7×7）。花色 3~8 种（7×7 简单关较低、8×8 挑战关较高、最高 8 种），滑块总数从 30 增至 105（恒为 3 的倍数）：前期 L4~16 堆叠 2~3 层（7×7 约 54~63 块、8×8 约 69~78 块），中期 L17~36 堆叠 3~4 层（7×7 约 63~75 块、8×8 约 78~90 块），后期 L37~60 最高堆叠 5 层 z=0..4（7×7 约 72~84 块、8×8 困难关 87~105 块），并逐关解锁四大机制（L7 起齿轮、L12 起冰封、L22 起钥匙锁链、L32 起棱镜，随章节依次解锁并复合；Δ13: 原 L6/L11/L21/L31 档位随 50→60 拼接 +1 平移）。总体难度随关卡编号 L1→L60 稳步提高（覆盖局部波浪）。每一关都由逆向生成算法离线构建或经自动求解器验证，保证在 7 格槽位限制下 100% 存在至少一条必胜路径；每关附带量化难度指标（最优解步数、解路径数、槽位压力峰值、启用机制数）。（Δ13 拼接铁律：原 50 关的滑块布局与预计算解 100% 原封不动保留复用——仅 1 关新生成插入 + 9 关尾部新生成追加，经 tools/expand-60.js 增量迁移。）

**Why this priority**: "60 关难度递进设计"是本项目两大核心价值轴之一，也是大赛评审核心。关卡系统与核心循环共同构成不可削减的 P1 基底。

**Independent Test**: 可独立测试——逐关加载关卡配置渲染棋盘并按难度参数矩阵核对网格尺寸/花色数/滑块数/机制引入档位；运行求解器对 60 关逐一验证可解性并核对难度指标。

**Acceptance Scenarios**:

1. **Given** 关卡 N ∈ [1,60]，**When** 加载该关，**Then** 其网格尺寸（L1=5×5、L2=6×6、L3=7×7、L4~60 按 7/7/8 三关一循环）、花色种类数、滑块总数（3 的倍数）、堆叠层数与启用机制集合符合阶段参数矩阵。
2. **Given** 任意一关的初始局面，**When** 运行自动求解器回溯验证，**Then** 求解器输出至少一条必胜路径及量化难度指标（最优解步数、解路径数、槽位压力峰值、启用机制数）。
3. **Given** 玩家完成第 N 关，**When** 结算结束，**Then** 自动进入第 N+1 关（第 60 关通关进入全通关庆祝终局）。
4. **Given** Level 4~60 中波浪挑战位（第 (id-4)%3==2 关，即 L6/L9/…/L51/L54/L57/L60 的 8×8 困难关），**When** 加载，**Then** 呈现卡点挑战型难度（较多滑块、更深堆叠、更高花色数与机制密度——难度评估分显著高于全程均值）；后期阶段（L32+）个位 5/0 的 7×7 关呈现图案解压爽关（滑块摆放为对称趣味图形、槽位压力与机制依赖显著更低）。
5. **Given** 全部 60 关关卡数据，**When** 交付验收，**Then** 附带由求解器生成的可解性验证报告，报告中 60/60 关全部可解。

### User Story 3 - 四大微创新机制（Priority: P2）

作为进入中高章节的玩家，我在基础方向阻挡之上遭遇四种递增机制并学会利用它们：

- **机制 A 齿轮滑块转向（L6+）**：场上带【齿轮标记】的滑块每当有十字相邻滑块飞出时自动顺时针旋转 90° 改变朝向，动态解开互锁路径（转向垫地面载体已取消，机制 A 仅保留齿轮滑块）。
- **机制 B 冰封滑块（L11+）**：被冰块包裹的滑块即使前方畅通也无法直接点击飞出，但可作为障碍物阻挡他人；每当收集槽成功触发 1 次三消，场上所有冰封滑块冰层厚度减 1，归零破冰变为普通滑块。
- **机制 C 钥匙与锁链（L21+）**：部分滑块被锁链锁在原地，需先让带【钥匙角标】的特定滑块飞出棋盘，才能自动解开对应锁链。
- **机制 D 变向棱镜（L31+）**：棋盘边缘或内部设有固定棱镜块（不可移走），滑块沿箭头冲向棱镜时不被弹回，而是折射 90° 从另一侧飞出棋盘进入收集槽。

**Why this priority**: 四大机制是"玩法融合微创新"核心价值轴的载体，支撑 60 关（Δ13 扩容后）的体验差异化；但其依赖核心循环与关卡系统先就绪，故为 P2。

**Independent Test**: 可分别在启用单一机制的章节关卡（L6+、L11+、L21+、L31+）独立测试每个机制的触发、反馈与机制间交互。

**Acceptance Scenarios**:

1. **Given** L6+ 某关中带齿轮标记的滑块与其十字相邻滑块，**When** 该相邻滑块飞出棋盘，**Then** 齿轮滑块立即顺时针旋转 90°，朝向变化在 UI 上即时可见。
2. **Given** L6+ 某关中带齿轮标记的滑块与其对角相邻滑块，**When** 该对角滑块飞出棋盘，**Then** 齿轮滑块不旋转（十字相邻才触发）。
3. **Given** L11+ 某关中冰层厚度 ≥1 的冰封滑块且其前方畅通，**When** 玩家点击它，**Then** 无法飞出（不可直接移除），但它仍阻挡其他滑块的前进射线。
4. **Given** L11+ 场上有冰封滑块，**When** 收集槽内触发一次三消，**Then** 场上所有冰封滑块冰层厚度各减 1；厚度归零的滑块破冰并变为普通可点击滑块。
5. **Given** L21+ 某关中被锁链锁定的滑块，**When** 对应带钥匙角标的滑块飞出棋盘，**Then** 锁链自动解开，该滑块恢复为普通可点击滑块。
6. **Given** L31+ 某关中滑块箭头指向棱镜块，**When** 玩家点击该滑块，**Then** 滑块不被弹回，而是折射 90° 从棱镜另一侧飞出棋盘并进入收集槽。
7. **Given** 第 4 章（L31-40）某关，**When** 加载，**Then** 棱镜与冰封、齿轮机制混排出现，机制间交互（如破冰依赖三消、齿轮随飞出转向）均按各自规则正确联动。

### User Story 4 - 辅助道具与评委调试面板（Priority: P3）

作为玩家，我在局内底部道具栏可使用两种道具：① 撤回上一步（Undo）；② 强制转向扳手（将任意一个滑块顺时针转 90°）。（Δ9 增量: 原③「移出槽位/暂存区」功能已整体移除——试玩发现点击暂存滑块会触发滑块复制分身破坏花色守恒，且双排空槽视觉冗余；滑块只在「棋盘 → 7 格收集槽 → 三消清除」单向守恒流转，或经 Undo 整体回滚。）作为评委，我可通过调试面板用 1~60（=LEVELS.length 动态）下拉框直接跳关、一键自动演示通关（Bot 沿求解器算出的最优解自动点击过关）、查看当前关卡难度评估分与机制标签；调试面板在移动端可隐藏/唤出且不影响正常游玩布局。

**Why this priority**: 道具与调试面板提升容错与评审效率，但属于体验增强层，须在核心玩法与关卡系统可用之后实现，故为 P3。

**Independent Test**: 可在任意关卡独立测试——逐个道具验证效果与次数限制；打开调试面板验证跳关、自动演示、Hint、难度指标与机制标签展示、移动端收起/唤出。

**Acceptance Scenarios**:

1. **Given** 局内已执行至少一步飞出操作，**When** 玩家点击"撤回上一步"，**Then** 棋盘与收集槽恢复该步操作前的状态（含被该步触发的旋转/破冰/解锁/三消等派生变化一并回滚）。
2. **Given** 任意普通或齿轮滑块，**When** 玩家使用扳手道具选择它，**Then** 该滑块顺时针旋转 90°；对冰封/锁链滑块该道具不可用（按 FR-024 适用性规则）。
3. **Given** 任意关卡，**When** 玩家查看道具栏，**Then** 仅显示「撤回」与「扳手」两种道具（移出槽位/暂存区已移除——Δ9）；棋盘滑块只能经飞出进入收集槽、经三消清除，不存在其他流转路径。
4. **Given** 调试面板已打开，**When** 评委在下拉框选择关卡 N，**Then** 游戏立即加载第 N 关。
5. **Given** 调试面板已打开，**When** 评委点击"自动演示通关"，**Then** Bot 沿求解器最优解逐步自动点击直至该关胜利（每步可见、节奏适中）。
6. **Given** 调试面板已打开，**When** 评委点击"Hint"或查看当前关卡信息，**Then** 面板显示下一步合法最优解提示，以及该关难度评估分与机制标签（含机制名称清单）。
7. **Given** 移动端窄屏运行，**When** 玩家收起调试面板，**Then** 面板隐藏、游玩布局不受影响，且可重新唤出。

### User Story 5 - 《万物出发！》动态生灵/载具图鉴、生态背景与治愈系 BGM（Priority: P2）

作为玩家，我在游玩 60 关（20 个"两简一难"三关循环）的过程中，体验与"滑块顺着箭头冲出棋盘"这一核心机制高度契合的动态题材与视听盛宴：滑块全面升级为天生会跑、会游、会飞的动态生灵与移动载具，随章节推进解锁陆地萌宠 → 碧海飞羽 → 奇幻远航三大生态图鉴；棋盘背景告别黑底，成为与关卡循环一一对应的阳光治愈系多层生态风景；每个"一难"挑战关开局弹出绿金激励横幅；全程伴随 Web Audio API 程序化合成的治愈系五声音阶 BGM。

**Why this priority**: US5 是"动态题材与视听体验层"，直接强化"滑块冲出棋盘"的核心心象（生灵/载具蓄势待发→冲出→离场）与 60 关三章节生态叙事的沉浸感；但完整依赖核心循环（US1）与 60 关体系（US2）先就绪，且不改变任何规则语义（纯表现层，不触碰 RulesEngine 口径），故为 P2（与 US3 同层、低于两大 P1 价值轴）。

**Independent Test**: 可独立测试——逐关抽查滑块图案是否来自对应阶段图鉴池（花色→图案映射、同花色图案恒一致）；核对 20 景背景与 `cycleIndex = Math.floor((level.id - 1) / 3)` 的严格对应；在挑战位关（L3/L6/…/L60）开局验证横幅弹出与 1.6 秒时长；首次交互后验证 BGM 自动播放与音效开关同步静音。

**Acceptance Scenarios**:

1. **Given** 关卡 N ∈ [1,21]（阶段一），**When** 加载该关，**Then** 滑块图案全部取自陆地萌宠篇图鉴池（Suit 0~14 共 15 种），单关出现的不同图案种数随关卡花色数 K（FR-008 区间 3~8）映射自该池（FR-033 §3 消解口径），同花色恒渲染同一图案。
2. **Given** 关卡 N ∈ [22,42]（阶段二），**When** 加载该关，**Then** 滑块图案全部取自陆地萌宠篇 + 碧海飞羽篇合并池（Suit 0~29 共 30 种），单关图案种数按 FR-033 §3 由关卡花色数 K 映射自合并池。
3. **Given** 关卡 N ∈ [43,60]（阶段三），**When** 加载该关，**Then** 滑块图案全部取自全池合并（Suit 0~44 共 45 种），单关图案种数按 FR-033 §3 由关卡花色数 K 映射自全池。
4. **Given** 任意堆叠滑块（1~5 层），**When** 渲染，**Then** 底座为 1:1 奶油白 3D 圆角正方体（底部立体厚度阴影 + 纯白高光内倒角），多层堆叠向左上角微量阶梯偏移并带层间阴影；左上角圆圈指示器与覆盖图案面部的半透明圆圈箭头均不存在，方向由朝向侧边缘内嵌的流光胶囊方向角标表示，图案居中完整展示、零遮挡。
5. **Given** 任意关卡 N ∈ [1,60]，**When** 加载，**Then** 背景为 `cycleIndex = Math.floor((level.id - 1) / 3)` 对应的 20 景生态风景之一（多层 SVG/Canvas 程序化绘制、零外部图片——宪章 III 红线不破），Cycle 1~7 陆地 / 8~14 蔚蓝 / 15~20 远航三段题材分布正确。
6. **Given** 循环内挑战位关卡（每 3 关一循环的第 3 关，即 L3/L6/L9/…/L60），**When** 开局，**Then** 屏幕中央弹出 1.6 秒绿金横幅"🔥 挑战关卡！只有 XX% 的玩家能一次通过这一关"（XX% 为关卡难度指标推导的确定性函数值，FR-036）。
7. **Given** 玩家已完成首次交互（点击任意滑块或按钮），**When** 检查音频状态，**Then** 治愈系 BGM（大调五声音阶柔和木琴/和弦循环）开始自动播放；**And** 音效开关关闭时 BGM 与音效同步静音。
8. **Given** 同关内两个同花色滑块，**When** 对比其图案，**Then** 两者渲染为完全相同的图鉴图案（花色→图案映射在本关内确定且一致）。

### Edge Cases

- **收集槽满但可三消**：第 7 格被占的同一点击内若恰好凑成第三同花色（满槽时飞入即三消），系统须判三消优先于爆槽——先消除再判负，玩家不因满槽瞬态被误判失败。
- **同一点击内连环触发**：一次飞出可能同时触发齿轮旋转→另一滑块解锁路径、三消→全场破冰等多重级联；所有级联须在一个原子回合内按确定顺序结算完毕，Undo 须能整体回滚。
- **互锁死局检测误报**：普通玩家可能尚未发现隐藏解（如先让某滑块受阻弹回以触发齿轮/利用道具）；死局判定须仅在实际无任何合法操作或道具无法挽救时触发，且基于求解器口径或穷举口径判定，避免误杀。
- **零滑块/空棋盘边界**：关卡生成必须保证初始滑块数 ≥1 且恒为 3 的倍数；三消后棋盘与槽同时清空即判胜，不出现"棋盘空但槽残留"的中间态（生成器须保证不存在该态，见 FR-029）。
- **收集槽花色种类溢出**：8 花色第 5 章，7 格槽中理论可同时滞留多于槽位数种未成三组的花色残片；生成器须保证在最优路径上任何时刻未完成三消的"开放花色数"不超过 5（7 格留余量），否则爆槽风险结构性偏高（见 FR-011 难度指标与 FR-030 验证门禁）。
- **锁链滑块作为阻挡**：被锁链锁定的滑块在解锁前同样阻挡射线；生成器须保证钥匙滑块在解锁前自身可达（其前方射线不被永远无法移除的锁链滑块堵死，见 FR-019）。
- **棱镜链**：滑块折射后从另一侧飞出棋盘须终止折射过程，不允许棱镜 A → 棱镜 B 的多重折射（FR-022 上限一次折射）；若关卡数据出现双棱镜对射布局，Generator 必须拒绝。
- **暂存区（已移除）**：原「移出槽位」道具与暂存区功能已整体删除（Δ9——试玩发现点击暂存滑块触发滑块复制分身破坏花色守恒的严重 Bug，且双排空槽视觉冗余）；道具仅剩 Undo 与 Wrench 两种。
- **受阻扣命的边界**：受阻扣减生命值/步数仅限挑战型高阶关卡（第 3 章起启用）；第 1、2 章受阻不扣命，避免新手挫败（FR-003 的分档规则）。
- **旋转方向歧义**：PRD 机制 A 曾同时描述"格子转向垫"与"齿轮标记滑块自动转向"两种载体；spec 统一收敛为齿轮滑块单一载体（Δ1 增量，地面转向垫取消），方向为顺时针 90°、触发口径为"十字相邻滑块飞出"（FR-013/FR-014）。
- **破冰时机歧义**：PRD 机制 B 给出"三消时全场冰层 -1（或十字相邻有滑块飞出时破冰）"两种可选口径；spec 统一主口径为"三消时全场冰层 -1"，十字相邻口径作为关卡数据可配置的变体（FR-016）。
- **图鉴抽样与既有花色数区间冲突（Δ14 关键消解）**：US5 要求单关抽样 6~22 种（分阶段递增），而 FR-008 既有口径为花色 3~8（爆槽风险结构性上限）且 Δ13 铁律要求原 50 关 tiles 100% 原封不动保留——重抽样会改写既有关卡数据的 suit 字段。冲突消解（FR-033 §3）：**图鉴池扩展不改写关卡数据 suit 值**；前端渲染层按阶段映射表将关卡内实际花色数 K（保持 3~8 不变）映射到该阶段图鉴池中的 K 个确定图案（确定性抽样、seed 可复现）；"45 种图鉴"为渐进解锁展示池（收集面板语义），非单关实际花色数上限。
- **阶段边界换装（Δ14）**：L21→L22、L42→L43 换章时图鉴池切换，同花色编号在两阶段映射到不同图案；切换 MUST 仅在换章边界发生（进度推进/跳关/Undo 均以当前关 id 计算阶段，不出现混合阶段图案）。
- **背景层与棋盘可读性冲突（Δ14）**：20 景背景 MUST 保证滑块、方向角标、机制标记（齿轮/冰封/锁链/钥匙/棱镜）的对比度与可辨识度不低于黑底基准（背景层与棋盘层间设半透明蒙版/暗角过渡，FR-035）。
- **激励横幅与开局输入竞态（Δ14）**：挑战关横幅弹出期间（1.6s）不阻塞玩家输入（非模态、不冻结核心循环）；横幅文本 XX% 对同一关卡恒定（难度指标确定性函数，重开/重放数值不变）。
- **BGM 自动播放策略（Δ14）**：浏览器 autoplay 政策下 BGM MUST NOT 在首次用户交互前发声；首次交互（PointerEvent/keydown 任一）后启动；页面失焦（visibilitychange→hidden）时暂停/静音、恢复可见时按开关状态续播；BGM 静音语义与既有 SoundManager 音效开关联动一致。
- **图案→花色守恒（Δ14）**：图鉴图案仅是渲染层花色标识的视觉替换，MUST NOT 影响三消判定、求解器口径、死局判定（RulesEngine 以 suit 整数值为准，FR-032 前后端口径 100% 一致铁律不破）。

## Requirements *(mandatory)*

### Functional Requirements

**核心循环（Core Loop）**

- **FR-001**: 系统 MUST 呈现 N×N 棋盘（N ∈ [4,8]，随关卡配置），每个滑块带花色图案与移动方向箭头（上/下/左/右）。
- **FR-002**: 玩家点击滑块时，系统 MUST 沿箭头方向检测射线直至棋盘边缘：无阻挡则滑块滑出棋盘飞入收集槽；有阻挡则滑块前冲碰撞后弹回原位，不进入收集槽。
- **FR-003**: 受阻碰撞 MUST 播放震动与受阻音效并给予明确受阻反馈；受阻扣减生命值（默认 3 点）或步数仅在挑战型高阶关卡（第 3 章起）启用，第 1、2 章不扣。
- **FR-004**: 收集槽 MUST 为固定 7 个空位；飞入的滑块自动与槽内已有同花色滑块归拢相邻排列。
- **FR-005**: 槽内同花色凑齐 3 个时系统 MUST 立即触发合并消除动效、腾出 3 个槽位并累加连击（Combo）计分。
- **FR-006**: 系统 MUST 按以下条件判定胜负：胜利 = 棋盘所有滑块移入收集槽且三消清空（棋盘 + 收集槽全空；Δ9: 暂存区已移除，不再参与胜利条件）；失败 = 收集槽满 7 格且未触发三消（爆槽）、生命值扣完、或棋盘环形互锁死局（所有剩余滑块前方均被彼此阻挡且无可行解救操作）。
- **FR-007**: 系统 MUST 提供 9:16 移动端竖屏比例视图：手机浏览器占满视口，PC 浏览器居中显示并预留侧边调试面板。

**50 关关卡系统**（Δ13 后为 60 关——本节口径已同步）

- **FR-008**: 系统 MUST 提供确定的 60 关参数配置（Δ11 大棋盘波浪架构 + Δ13 增量扩容拼接），网格排布铁律：
  - **Level 1**：固定 5×5（新手引导关，底层满铺 + 局部 2 层堆叠，总滑块数 27 或 30）。
  - **Level 2**：固定 6×6（进阶过渡关，底层满铺 + 2 层堆叠，总滑块数 42 或 45）。
  - **Level 3**：7×7 新手循环 1 困难关（底层满铺 + 局部 2~3 层堆叠，总滑块数 54~60，无机关；Δ13 新增插入关）。
  - **Level 4~60**：全部 7×7 或 8×8 大棋盘，严格按「每 2 个 7×7 相对简单关 + 1 个 8×8 困难挑战关」三关一循环排列（L4=7×7简, L5=7×7简, L6=8×8难; L7/L8=7×7, L9=8×8……直至 L60=8×8；挑战位 = (id-4)%3==2）。
  - 阶段参数（总体难度随关号稳步提高，覆盖局部波浪；Δ13 章区间 = 3×20 大阶段：ch1 L1-20 / ch2 L21-40 / ch3 L41-60）：
    - 前期 L4~16：堆叠 2~3 层；7×7 总块数约 54~63，8×8 约 69~78；花色 3~6；L7 起齿轮、L12 起冰封。
    - 中期 L17~36：堆叠 3~4 层；7×7 约 63~75，8×8 约 78~90；花色 4~8；L22 起钥匙锁链、受阻扣命启用。
    - 后期 L37~60：最高堆叠 5 层（z=0..4）；7×7 约 72~84，8×8 困难关 87~105；花色 5~8；L32 起棱镜与全机制复合。
  - 7×7 简单关采用较低花色数与较浅阻挡链；8×8 挑战关采用更多花色（最高 8 种）、更深跨层拓扑阻挡与更高机制密度（恒为 3 的倍数、底层 z=0 满铺除棱镜格）。
  - **Δ13 拼接铁律**：50→60 扩容 MUST 采用增量迁移（tools/expand-60.js）——原 50 关 tiles/prisms/cfg/solutionMoves 100% 原封不动保留（新 L1/L2 原样复用、原 L3~L50 平移为新 L4~L51 仅改 id/chapter/name），仅新生成 10 关（新 L3 插入 + 新 L52~L60 追加，均经 Generator 三重验证 + Solver 门禁 + 内嵌 solutionMoves）；严禁全量重生成。
- **FR-009**: 关卡数据 MUST 由离线流水线生产：逆向生成器（从清空状态反向推入三消图块组）生成候选 → 自动求解器回溯验证可解性 → 导出纯静态配置文件由前端直接读取；前端运行时 MUST NOT 执行关卡生成逻辑。
- **FR-010**: 每一关 MUST 100% 存在至少一条必胜通关路径（在 7 格槽位限制下）；未经可解性验证的关卡数据不得进入交付物。
- **FR-011**: 每一关 MUST 附带量化难度指标：最优解步数、解路径数、槽位压力峰值、启用机制数；难度指标支撑难度评估分计算。
- **FR-012**: 关卡序列 MUST 呈现交替节奏（Δ11 波浪锯齿）：8×8 挑战位关卡（三关一循环的第三关）难度评估分显著高于全程均值；后期阶段个位 5/0 的 7×7 关为图案解压爽关（滑块摆放为对称趣味图形且高连击率，难度评估分显著低于全程均值）。

**机制 A：齿轮滑块转向（L6+）**

- **FR-013**: 场上带齿轮标记的滑块 MUST 在"十字相邻滑块飞出棋盘"事件发生时自动顺时针旋转 90° 改变朝向（对角相邻滑块飞出不触发）。
- **FR-014**: 转向载体统一为齿轮滑块（地面转向垫载体取消——Δ1 增量）；齿轮转向结果 MUST 即时在 UI 上可见。齿轮与扳手道具共用统一的"顺时针 90°"转向规则（`(d+1)%4`）。

**机制 B：冰封滑块（L11+）**

- **FR-015**: 冰封滑块 MUST 无法被直接点击飞出（即使前方畅通），但 MUST 作为障碍物阻挡其他滑块的前进射线；冰层厚度为正整数（默认 1，关卡可配置更厚）。
- **FR-016**: 每当收集槽成功触发一次三消，场上所有冰封滑块冰层厚度 MUST 各减 1；厚度归零后破冰变为普通可点击滑块。关卡数据可配置变体口径：十字相邻有滑块飞出时冰封滑块破冰。
- **FR-017**: 冰层剩余厚度 MUST 在 UI 上可见（视觉上呈现冰层厚度差异）。

**机制 C：钥匙与锁链（L21+）**

- **FR-018**: 被锁链锁定的滑块 MUST 固定原地（无法点击飞出）并阻挡射线，直至对应钥匙滑块飞出棋盘后自动解锁。
- **FR-019**: 带钥匙角标的滑块 MUST 与特定被锁滑块形成明确的配对关系；钥匙飞出时自动解开配对锁链（一把钥匙可配对一或多条锁链，配对数由关卡数据配置）。生成器须保证钥匙滑块在解锁前自身可达（其前方射线不被无法移除的锁链滑块永久堵死）。
- **FR-020**: 锁链与钥匙的配对关系及其解锁依赖 MUST 在 UI 上可辨识（角标/链路提示）。

**机制 D：变向棱镜（L31+）**

- **FR-021**: 棋盘边缘或内部 MUST 可设固定棱镜块（不可移走、非滑块、非普通障碍）；滑块沿箭头冲向棱镜时 MUST 不被弹回，而是折射 90° 从另一侧飞出棋盘并进入收集槽。
- **FR-022**: 滑块的折射次数 MUST 上限为 1（一次飞出最多经一次棱镜折射后必须离场）；Generator MUST 拒绝可能形成棱镜对射循环的布局。
- **FR-023**: 棱镜块 MUST 在视觉上与普通障碍/滑块显著区分。

**道具系统**

- **FR-024**: 局内道具栏 MUST 提供两种道具（Δ9: 原③「移出槽位/暂存区」已整体移除——试玩发现暂存滑块点击复制分身 Bug 破坏花色守恒；滑块只在「棋盘 → 收集槽 → 三消」单向守恒流转，或经 Undo 整体回滚）：
  1. **撤回上一步（Undo）**：恢复该步操作前棋盘与槽的完整状态，含该步触发的旋转/破冰/解锁/三消等派生变化一并回滚；一次 Undo 仅回滚最近一回合的原子操作集。
  2. **强制转向扳手**：将任意一个滑块顺时针转 90°；对冰封/锁链滑块不可用，对普通与齿轮滑块可用。
- **FR-025**: 道具 MUST 有使用次数来源与限制（默认每关各 1 次，可被关卡配置覆盖）。
- **FR-026**: （已随暂存区移除而废止——原「暂存区满 3 时道具不可用」约束不再适用；保留编号以维护 FR 索引稳定。）

**调试面板（评委专用）**

- **FR-027**: 调试面板 MUST 支持：1~60 关（LEVELS.length 动态）下拉框直接跳关、重置当前关、AI 提示下一步合法最优解（Hint）、一键自动演示通关（Auto-Play Bot 沿求解器最优解自动点击过关，每步可见）、显示当前关卡难度评估分与机制标签。
- **FR-028**: 调试面板在移动端 MUST 可隐藏/唤出，且不影响正常游玩布局。

**关卡生成与可解性（Generator / Solver）**

- **FR-029**: 逆向生成器 MUST 从清空状态反向推入三消图块组构建关卡候选，保证：初始滑块数 ≥1 且为 3 的倍数、不存在"棋盘空但槽残留"的终局态、最优解路径上任何时刻未完成三消的开放花色数不超过 5（在 7 格槽内留安全余量），并输出候选布局与预估难度。
- **FR-030**: 自动求解器 MUST 对每关做回溯求解，验证 7 格槽位约束下的必胜路径存在性，输出可解性结论与量化难度指标（最优解步数、解路径数、槽位压力峰值、启用机制数）；不可解候选回炉重生成。
- **FR-031**: 关卡数据任何变更 MUST 触发 Solver 全量重验证并更新验证报告；交付物 MUST 附带 60/60 关可解的验证报告（Δ13 扩容后）。
- **FR-032**: 前端死局判定口径（爆槽/扣命/互锁）与求解器死局口径 MUST 一致，确保"玩家实际可玩局面集合 = 求解器验证过的可解局面集合"。

  3. **阶段三（L43~L60，Cycle 15~20）新增【奇幻远航篇】Suit 30~44（池扩至 45 种）**：小火箭、飞碟、小飞机、直升机、热气球、小帆船、小火车、甲壳虫车、黄色巴士、小电驴、滑板、风筝、流星、彗星、土星环。
  4. **§3 图鉴抽样与既有口径的消解条款（MUST）**：图鉴池扩展 MUST NOT 改写关卡数据（`src/data/levels.js`）的 suit 字段与既有花色数口径（FR-008 的 3~8 与 Δ13 原关保留铁律不变——图案替换是纯渲染层变更）。前端渲染层按**阶段映射表**将关卡内实际花色数 K（3~8 不变）映射到该阶段图鉴池的 K 个确定图案（确定性抽样：以 seed + level.id + 阶段号可复现，同关内 suit→图案映射唯一）。US5 原始需求的"单关抽样 6~14 / 12~18 / 15~22 种"作为**展示池目标口径**记录于本条（图鉴/收集面板的渐进解锁语义——玩家跨关累计可见 45 种），单关实际并存图案数以关卡花色数 K 为准。"6~14 / 12~18 / 15~22"与"3~8"的区间重叠部分按 K 落点直接满足（如阶段一 K≥6 的关卡即处于 6~14 区间内）。
  5. 同一花色（suit 值）在同一关卡内 MUST 恒映射同一图案；三消判定、Solver 口径、死局判定 MUST 100% 以 suit 整数值为准（FR-032 铁律不破，图案仅为视觉标识替换）。

**底座工艺与方向标识（US5/FR-034）**

- **FR-034**: 滑块底座与方向标识 MUST 采用以下工艺口径（替换旧视觉，属渲染层变更）：
  1. **底座**：1:1 奶油白 3D 圆角正方体，带底部立体厚度阴影与纯白高光内倒角；多层堆叠（1~5 层）通过向左上角微量阶梯偏移与层间阴影展现真实空间立体感。
  2. **旧指示器移除**：MUST 彻底移除左上角圆圈指示器与覆盖在图案面部的半透明圆圈箭头（两类旧方向视觉元素全部下线）。
  3. **流光胶囊方向角标**：在滑块朝向的那一侧边缘内嵌"流光胶囊"方向角标（胶囊沿方向侧边布置、流光为程序化渐变动画）；图案本身居中完整展示、零遮挡。
  4. 方向语义（上/下/左/右 → 前进射线）MUST 与既有 FR-001/FR-002 完全一致；新角标仅替换视觉表达，不改变命中判定与射线计算。
  5. 新视觉口径 MUST 保持可辨识度红线：方向角标须一眼可辨（对比度、尺寸下限），机制标记（齿轮/冰封/锁链/钥匙/棱镜）叠加位置与新底座兼容，不互相遮挡。

**生态场景背景（US5/FR-035）**

- **FR-035**: 游戏背景 MUST 采用 20 套与 20 个三关循环严格对应的多层 SVG/Canvas 阳光治愈系生态风景（`cycleIndex = Math.floor((level.id - 1) / 3)`，cycleIndex 0~19 对应 20 景；用户口径 Cycle 1~20）：
  1. **题材分布**：Cycle 1~7 陆地风光（阳光牧场/花海/麦田等）；Cycle 8~14 蔚蓝天地（海滩/珊瑚湾/彩虹谷/云海等）；Cycle 15~20 远航胜景（热气球晨光/海港/星河/云海金顶等）。
  2. **对应铁律**：关卡 id → cycleIndex → 背景景序严格一一对应，同一循环内 3 关共享同一景背景（含其 2 简关与 1 难关）。
  3. **程序化红线**：全部 20 景 MUST 由 Canvas 2D / 内联 SVG + 渐变程序化绘制，零外部图片资源（宪章 III）；多层视差/缓慢动效允许（性能预算内，见 plan 阶段）。
  4. **可读性保证**：背景层与棋盘层间 MUST 设半透明蒙版/暗角过渡，滑块、方向角标与机制标记对比度不低于黑底基准。
  5. 背景为纯表现层：MUST NOT 影响命中判定、射线计算与任何规则语义。

**困难关激励横幅（US5/FR-036）**

- **FR-036**: 每逢每个三关循环的第 3 关（挑战位关卡——FR-008 口径的 (id-4)%3==2 位 + L3（新手循环 1 困难关），即 L3/L6/L9/…/L60 共 20 关）开局时，系统 MUST 在屏幕中央弹出 1.6 秒绿金横幅："🔥 挑战关卡！只有 XX% 的玩家能一次通过这一关"：
  1. "XX%" 为由关卡难度指标（FR-011：最优解步数、解路径数、槽位压力峰值、启用机制数、难度评估分）推导的**确定性函数值**：同一关卡重开/重放/跳关后横幅数值恒定；具体函数由 plan 阶段确定（spec 只约束确定性与合理值域）。
  2. 横幅 MUST 非模态：弹出期间不阻塞玩家输入、不冻结核心循环（rAF 与判定照常运行）。
  3. 横幅 1.6 秒后自动消散，无手动关闭交互；同一次开局会话内不重复弹出（重开本关可再次弹出）。
  4. 横幅风格：绿金配色（挑战主题激励语气），位置屏幕中央、不影响对棋盘已可交互区域的持续操作。

**程序化治愈系 BGM（US5/FR-037）**

- **FR-037**: SoundManager MUST 新增基于 Web Audio API 的治愈系 BGM：
  1. **音乐形态**：大调五声音阶（C 大调五声：C D E G A）柔和木琴（程序化合成的短促衰减正弦/三角波敲击音色）与柔和和弦循环，循环结构（如 4~8 小节循环，具体由 plan 阶段确定）。
  2. **自动播放策略**：玩家首次交互（PointerEvent / keydown 任一）后自动开始播放（浏览器 autoplay 政策合规——首次交互前 MUST NOT 发声）。
  3. **静音联动**：BGM MUST 受既有音效开关控制——开关关闭时 BGM 与音效同步静音（SFX 与 BGM 同开关或 BGM 单独开关由 plan 阶段定夺，spec 只约束静音联动必须存在）。
  4. **页面可见性**：页面失焦（visibilitychange → hidden）时 BGM 暂停或静音，恢复可见时按开关状态续播。
  5. **零外部资源**：全部音符 MUST 由 Web Audio API 纯代码实时合成（宪章 III 红线），无任何 .mp3/.wav 等音频文件依赖。
  6. BGM 为纯表现层：MUST NOT 影响游戏逻辑、判定与持久化状态。

### Key Entities *(include if feature involves data)*

- **Level（关卡）**：60 关静态配置实体（Δ13 扩容后）。属性：编号、章节、网格尺寸 N、花色数 K、滑块清单（位置/花色/方向/初始机制标记）、机关格清单（棱镜）、全局参数（生命值默认 3、道具次数、破冰口径、扣命规则）、难度指标（最优解步数、解路径数、槽位压力峰值、启用机制数、难度评估分）、机制标签。
- **Tile（滑块）**：棋盘可交互单元。属性：位置（行/列）、花色、方向（上/下/左/右）、机制标记（齿轮/冰封（含冰层厚度）/锁链（含钥匙配对）/钥匙）。关系：被点击→沿方向射线移动或受阻弹回；飞出→进入 Dock。
- **Dock Slot（收集槽）**：7 格槽位容器。关系：接收飞出滑块、同花色归拢、3 个同花色触发三消并腾位。
- **Staging Area（暂存区，已移除）**：原容量 3 临时容器与「移出槽位」道具已整体删除（Δ9——点击暂存滑块触发复制分身 Bug 破坏花色守恒 + 双排空槽视觉冗余）；滑块流转仅限「棋盘 → Dock → 三消」，或经 Undo 整体回滚。
- **Prism（棱镜）**：棋盘固定机关格（非滑块）。属性：格子位置、类型（`/` 或 `\`）、折射规则参数。
- **Solver Report（可解性验证报告）**：60 关验证产物（Δ13 扩容后）。属性：关卡号、可解性布尔、最优解步数、解路径数、槽位压力峰值、启用机制数、生成时间戳。
- **Bestiary Entry（图鉴条目，Δ14）**：45 种动态生灵/载具图鉴实体（纯渲染层展示池）。属性：Suit 编号（0~44）、名称（如跳跳蛙/小火箭）、生态篇章（陆地萌宠/碧海飞羽/奇幻远航）、程序化绘制参数（Canvas 2D / 内联 SVG 图形语汇，零外部图片）。关系：经 Stage Suit Mapping 映射后作为滑块花色的视觉标识。
- **Eco Background（生态背景，Δ14）**：20 景治愈系生态风景实体。属性：cycleIndex（0~19）、题材段（陆地/蔚蓝/远航）、多层图层程序化绘制参数（天空/远景/中景/近景渐变与形体）。关系：按 `cycleIndex = Math.floor((level.id - 1) / 3)` 与关卡严格对应，同一循环 3 关共享。
- **Stage Suit Mapping（阶段花色映射表，Δ14）**：渲染层映射规则实体（FR-033 §3 消解机制的核心载体）。属性：生态篇章区间（L1~21 / L22~42 / L43~60）、对应图鉴池（Suit 0~14 / 0~29 / 0~44）、确定性抽样算法参数（seed = f(level.id, 阶段号)）。关系：输入关卡 id 与 suit 值 → 输出唯一图鉴图案；不写回关卡数据（levels.js 的 suit 字段与花色数 K 永不被改写）。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 全部 60 关经自动求解器验证 100% 存在必胜路径（60/60 可解，附验证报告）。
- **SC-002**: 评委使用调试面板跳关 + 自动演示可在 10 分钟内遍历 60 关并完成至少 10 关的机制深度验证。
- **SC-003**: 双击 `index.html`（或单条静态服务命令）即可开始游玩，无任何安装步骤；首屏可交互时间在主流桌面/手机浏览器上不超过 3 秒。
- **SC-004**: 60 关难度递进曲线可量化验证：最优解步数与难度评估分随关卡编号总体单调不减（章均值单调 + 全程斜率 ≥0，关卡内允许局部波动；L4~60 呈「2 简 1 难」7/7/8 波浪锯齿交替形态——8×8 挑战关显著难于 7×7 简单关）。
- **SC-005**: 新玩家（无引导）在第 1 关无需文字教程、30 秒内完成首次有效滑块飞出操作的比例不低于 80%（可用小规模真人测试或埋点验证）。
- **SC-006**: 交付物中不存在任何外部二进制素材依赖（图片/音频/字体文件数为 0），全部视觉与音频由程序化手段生成。
- **SC-007**（Δ14）: 三大生态阶段图鉴共 45 种程序化绘制的动态生灵/载具图案全部可正确渲染：同一关卡内同花色恒同图案、跨阶段池切换仅在换章边界发生、`levels.js` 关卡数据 suit 字段与花色数 K 在图鉴上线前后逐字节一致（Δ13 保留铁律不被破坏）。
- **SC-008**（Δ14）: 视听体验层验收可量化：20 景背景与 20 个三关循环严格一一对应（cycleIndex 公式核对 0 遗漏 0 冲突）；挑战位关卡开局 1.6 秒激励横幅触发率 20/20（L3/L6/…/L60）；BGM 在首次交互后自动播放且音效开关同步静音（autoplay 政策合规，无控制台报错）。

## Assumptions

- 目标用户为大赛评委与休闲游戏玩家；游戏完全去美术化、去叙事化，无角色、剧情、世界观包装（遵宪章原则 I）。
- 技术栈遵宪章原则 II/III：原生 HTML5 + CSS3 + Vanilla JS（ES6 Modules）、零构建链、零外部静态资源；音效由 Web Audio API 实时合成；输入统一 PointerEvents；关卡数据为前端直接读取的纯静态 JSON/JS 配置（本 spec 不指定具体文件格式细节，留给 plan 阶段）。
- 关卡数据由 Node.js 离线工具（Generator/Solver）生产（宪章唯一允许的 Node 用途）；本 spec 描述 Generator/Solver 的产品行为契约（输入参数矩阵、输出格式、验证门禁），不指定算法内部实现。
- 单人单机体验：无账号、无后端、无联网多人；进度以本地方式延续（具体持久化手段由 plan 阶段决定）。
- 每关滑块总数为 3 的倍数（PRD 明示）；花色数与槽位约束共同构成爆槽风险的难度来源。
- 生命值默认 3 点、收集槽 7 格、道具 2 种（Undo/扳手——Δ9 移除暂存区后）、均为既定值；道具默认每关各 1 次为假设默认（可被关卡配置覆盖）。
- 机制 A 转向载体统一为齿轮滑块（转向垫取消，FR-013/FR-014，Δ1）；机制 B 破冰主口径为"三消时全场冰层 -1"，十字相邻口径作为可配置变体（FR-016）；道具③暂存区已整体移除（Δ9——复制分身 Bug，取代原 Δ3 增量）；胜利条件不再含暂存区（FR-006，Δ9）。
- 关卡机制引入档位（L6/L11/L21/L31）为 PRD 硬性要求，覆盖宪章要求的机制标签展示。
- "解路径数"指标定义：求解器在限定搜索预算内找到的必胜路径条数（量级/计数口径由 plan 阶段确定，spec 只要求指标存在且可复现）。
- 竞赛交付时间盒内不包含成就、社交分享、商城、本地化多语言等范围外功能（遵宪章原则 I 的赛后 backlog 处理）。
- （Δ14）US5 题材化是对宪章原则 I"去美术化"定位的**用户明确裁定的放宽**：题材仅落地为程序化绘制的图案/背景/音频表现层（宪章 III 技术红线零突破——仍零外部资源、Web Audio 合成），不引入剧情文本、世界观叙事、角色对话等叙事包装；本次修订仅记录该裁定，宪章版本不变（如需正式放宽可在赛后以宪章修订流程升级）。
- （Δ14）图鉴/背景/横幅/BGM 均为纯渲染层与音频层需求，不触碰 RulesEngine 规则语义与 Solver 口径（FR-032 前后端一致铁律不破）；关卡数据文件 levels.js 不因 Δ14 发生任何字节级变更（Δ13 保留铁律延续）。
- （Δ14）"单关抽样 6~14 / 12~18 / 15~22 种"为 US5 原始需求的展示池目标口径（图鉴渐进解锁语义）；单关实际并存图案数以关卡花色数 K（FR-008 的 3~8）为准，二者经 FR-033 §3 消解条款统一（渲染层确定性映射，不改关卡数据）。
- （Δ14）挑战位口径统一说明：FR-036 的横幅触发集合 = FR-008 波浪挑战位 (id-4)%3==2（L6/L9/…/L60 共 19 关）∪ 新手循环 1 困难关 L3，合计 20 关 = 20 个三关循环各含 1 难关，与"每 3 关一循环的第 3 关"（L3/L6/…/L60）的用户口径一致。
- （Δ14）BGM 的 SFX/BGM 开关粒度（同开关 or BGM 独立开关）、五声音阶具体音色参数、循环小节结构、20 景背景的具体构图清单（20 景名称逐一枚举）与多层视差动效的实现方式，均留给 plan 阶段决策；spec 只锁定题材分段与对应关系。
