## 1. 产品定义

《Glide Critters · 萌灵飞滑》是一款**零构建、零运行时依赖**的竖屏 H5 三消益智游戏：卡牌只肯朝它箭头所指的方向飞；凑齐三张同族萌灵，它们才会在待消槽里合体消散。

**三条价值轴**：

| 价值轴 | 载体 | 规模 |
|---|---|---|
| **顺向飞滑核心循环** | 方向射线判定 + 同层凌空飞越 + 7 格待消槽 + 三消合体 | 单局 60~141 张卡牌 |
| **72 关递进关卡设计** | 离线 Generator + Solver 流水线，100% 机判可解 | 72 关 · 6 画卷 · 4 类机关 |
| **治愈系奇幻探险表现层** | 96 种 3D 萌宠图鉴 + 垂直雨幕落子进场 + 原位微跃柔光消除 + 混合双轨声学 | 6 幅画卷背景 · 8 轨原声 |

## User Scenarios & Testing *(mandatory)*

### User Story 1 — 顺向飞滑核心循环（Priority: P1）

我在 9:16 竖屏里看到一张多层堆叠的棋盘，每张卡牌带花色图案与一枚方向箭头。我点击它：若沿箭头方向的**同层**射线上没有任何阻挡，它凌空飞出棋盘、飞入顶部 7 格待消槽；若有阻挡，它前冲碰撞、弹回原位并发出清脆双叩，连击清零（**不扣生命**——生命机制已下线）。飞入的卡牌与同花色自动归拢，凑齐 3 张立即合体消除、腾出槽位并累加连击。当棋盘与待消槽同时清空，我获胜。

**Why this priority**：唯一的核心循环，其余一切机制的承载基底；单独实现即构成可玩 MVP。

**Independent Test**：加载 L1 完整通关一次——点击飞出 / 受阻弹回 / 槽内归拢 / 三消合体 / 清盘判胜。

**Acceptance Scenarios**

1. **Given** 某卡牌射线畅通，**When** 点击，**Then** 沿箭头飞出并落入待消槽，槽内同花色相邻归拢。
2. **Given** 前方同层有阻挡，**When** 点击，**Then** 前冲弹回、播放微震与双叩、不进入槽位、`comboCount` 归零。
3. **Given** 槽内已有 2 张同花色，**When** 第 3 张飞入，**Then** 立即触发合体消除、腾空 3 槽、连击 +1。
4. **Given** 槽内 7 格已满且未成三，**When** 第 7 张落定，**Then** 判负（`lost_burst`）。
5. **Given** 棋盘与槽同时清空，**When** 最后一次消除结束，**Then** 判胜并进入结算。

### User Story 2 — 72 关递进关卡与可解性保证（Priority: P1）

我从 L1 开始，经历 3 个 24 关大阶段、6 幅画卷、72 关严格递进的关卡。每关由离线逆向生成器构建、由回溯求解器验证在 7 格槽位限制下**必然存在必胜路径**，并附带量化难度指标。棋盘布局为奇偶层半格错位堆叠 + 36 套图形掩码成型，难度按「2 简 1 难」波浪锯齿推进。

**Why this priority**：与核心循环并列的两大价值轴之一，大赛评审核心。

**Independent Test**：逐关加载核对网格 / 花色数 / 层数 / 掩码 id；`node tools/solver.js` 全量验证 72/72 可解。

**Acceptance Scenarios**

1. **Given** 关卡 N ∈ [1,72]，**When** 加载，**Then** 网格尺寸、花色数 K、层高、掩码模板 id 与机制集合符合 FR-008 参数矩阵。
2. **Given** 任意初始局面，**When** 运行求解器，**Then** 输出 ≥1 条必胜路径与量化难度指标。
3. **Given** 全部 72 关，**When** 交付验收，**Then** 附带 72/72 可解的验证报告。
4. **Given** 8×8 挑战位（`(id-4)%3==2`，共 23 关），**When** 加载，**Then** 难度评估分显著高于全程均值。

### User Story 3 — 四类特殊机关（Priority: P2）

- **齿轮滑块（L7 起）**：十字相邻卡牌飞出时自动顺时针旋转 90°（`d = (d+1)%4`），动态解开方向对冲。
- **冰封滑块（L12 起）**：冰层包裹时完全不可点击，但仍阻挡射线；每次三消全场冰层各减 1（`iceMode: "triple"` 主口径），归零解冻。
- **钥匙与锁链（L22 起）**：锁链卡牌固定原地并阻挡射线，对应钥匙卡牌飞出后自动解锁（一钥可配多锁）。
- **变向棱镜（L39 起）**：固定折射块贯穿全层高，卡牌撞上后折射 90° 从另一侧飞出，单次飞出最多折射 1 次。

**Independent Test**：在各自首现关（L7 / L12 / L22 / L39）逐一验证触发、反馈与机关交互。

**Acceptance Scenarios**

1. 齿轮的十字相邻卡牌飞出 → 顺时针转 90°；对角相邻飞出 → 不转。
2. 冰封卡牌前方畅通时点击 → 无法飞出；三消后全场冰层 -1。
3. 钥匙卡牌飞出 → 配对锁链解锁；解锁前锁链仍阻挡射线。
4. 箭头指向棱镜 → 折射 90° 飞出而非弹回；双棱镜对射布局被 Generator 拒绝。

### User Story 4 — 三大道具与评委调试面板（Priority: P3）

我在局内可用三枚道具：**撤销**（整体回滚一步，含派生变化）、**灵犀三消**（无视阻挡与压制锁定，强制完成一次同花色三消）、**乾坤洗牌**（重排棋盘花色与朝向，保证洗后仍可解）。作为评委，我通过调试面板跳关、重置、看 Hint、一键自动演示、查看难度指标与机制标签；移动端面板可隐藏/唤出。

**Independent Test**：逐道具验证效果与次数限制；偏离预设解后复测 Hint 与自动演示必须立即生效。

**Acceptance Scenarios**

1. 撤销 → 棋盘与槽恢复至该步前，旋转/破冰/解锁/三消派生变化一并回滚。
2. 灵犀三消 → 场上同花色 ≥3 时必成功，移除后零悬空违规。
3. 乾坤洗牌 → 洗后仍存在必胜路径，每花色总数仍为 3 的倍数。
4. 中途偏离 `solutionMoves` 后 Hint / 自动演示仍立即生效（≤2s 给出首个合法点击）。
5. 音效复选框勾选态与 `muted` 严格同向；面板显示当前画卷主题名。

### User Story 7 — 局内信息层级、进场编舞与原位微跃消除（Priority: P1）

局内顶部为导航栏 + IQ 指数条 + 7 格待消槽；进入关卡时全盘卡牌**从待消槽上空的统一落距垂直砸落**——前排先落、后排紧随的齐刷刷雨幕，触底 `4~6px` 微弹即定格，绝不横飞、绝不倾斜、绝不整盘铁板一块同速下落；三消时三张卡牌**各自留在自己的槽位里**原地轻跃、泛起纯白柔光后缩小消散，再由剩余卡牌顺滑左补——全程不出现任何跨槽横移、光环 / 星芒 / 碎块 / 粒子。

**Acceptance Scenarios**

1. 进关后卡牌自待消槽上空统一落距垂直落下，全程 `|dx| = 0` 且角度 `0°`，总时长 `380~420ms`（30 张与 141 张同档），首末排起跑差 ≥`150ms`，触底挤压 `4~6px`，首帧相位 `0%`。
2. 三消演出 `200ms` 完成，三张牌全程**零横向位移**（`|dx| ≤0.5px`、零跨槽、零穿槽框），`#vfx-canvas` 在三消窗口内 `alpha > 2` 像素数恒 `0`。
3. 待消槽与棋盘包围盒不相交；IQ 初值 `50`、上限 `200`。

### Edge Cases

- **满槽同时成三**：第 7 格落定即凑成三消时，三消优先于爆槽——先消除再判负。
- **单次点击多级联**：飞出可同时触发齿轮旋转 → 路径解锁 → 三消 → 全场破冰；全部级联在一个原子回合内按固定顺序（齿轮 → 钥匙解锁 → 破冰 → 入槽 → 三消）结算，Undo 可整体回滚。
- **互锁死局误报**：正常对局中「环形互锁」不可达（运行期自愈 + 洗牌兜底），该失败条件仅作防御性兜底。
- **零滑块 / 空棋盘**：初始卡牌数 ≥1 且恒为 3 的倍数；不出现「棋盘空但槽残留」的中间态。
- **开放花色数**：最优路径上任何时刻未成三的开放花色数不超过 5（7 格留余量），否则爆槽风险结构性偏高。
- **锁链阻挡**：解锁前锁链卡牌同样阻挡射线；Generator 保证钥匙在解锁前自身可达。
- **棱镜链**：单次飞出最多折射 1 次；双棱镜对射布局由 Generator 拒绝。
- **进场与飞行的互斥**：进场只做「垂直下落 + 触底微弹」，飞行只做「棋盘 → 槽位」位移；两者 MUST NOT 复用同一变换通道，进场未结束时 MUST NOT 起播飞行。
- **进场总时长 vs 逐张可辨**：`141` 张牌若保持 `9ms` 逐张步长需 `≈1440ms`，与 `380~420ms` 预算算术互斥——故采用「同排成组齐落 + 行波推进」而非「逐张排队」。
- **落子与已落定牌的视觉重叠**：下落中的牌必然与其同列上方已落定的牌在画面上短暂重叠（雨幕的物理必然）——遮挡 MUST 沿用静态 `(z,r,c)` 比较器（同层下方牌盖上方牌、`z` 更大者恒盖下层），MUST NOT 因「正在下落」单独置顶或临时改序。
- **画布上边界**：卡牌起始点位于待消槽上空，整段落距**必然**越出棋盘画布上边界——越界段 MUST 沿用 FR-029 的**两画布互补裁剪**（`#vfx-canvas` 接续），MUST NOT 新增第三块画布；越界高度上限由 `0.5 × 卡面边长` 放宽至 `3.4 × 卡面边长`（允许整张牌起始于画布之外），且 MUST 在 `#app` 视口上沿处硬裁剪（MUST NOT 画出视口外或盖住导航栏图标）。
- **闸门期的遮挡与打断**：`startDeal()` 之后、`t0` 之前若弹窗 / 大厅 / 结算层重新出现、棋盘画布被隐藏或尺寸归零、页面转入后台（`visibilityState !== 'visible'`），闸门 MUST 复位（帧计数清零、`t0` 作废）；遮挡解除后 MUST 重新数满 2 个真实可见帧才记 `t0`——MUST NOT 把「被弹窗盖住时画出的帧」计入闸门（否则玩家看到的画面已从半空开始 = 瞬移）。
- **闸门看门狗**：`startDeal()` 后每 `1200ms` MUST 复查一次闸门；仍未开闸（连续被遮挡、rAF 停摆、绘制异常）MUST **重挂下一轮复查**（MUST NOT 在遮挡期静置、MUST NOT 丢弃整段演出）；累计超 `8000ms` 才强制收口——或直接记 `t0` 开播，或整盘静置落定；MUST NOT 让 `isDealing()` 永久为真、MUST NOT 让棋盘长期停在起始态（开局卡死）。
- **三消三槽不相邻**：三张同花色卡牌在槽内**可能互不相邻**（如第 1 / 3 / 6 格）。演出 MUST 各自在原槽内完成、MUST NOT 产生任何槽与槽之间的横向位移——「跨越中间卡牌滑向中心」的旧口径已废止（附录 B）。
- **编舞变体的确定性**：辐射变体 MUST 由关卡静态配置确定性选取，同一关重开 MUST 恒为同一变体（MUST NOT 随机抽取、MUST NOT 会话内漂移）。
- **并发三消**：`200ms` 窗口内两次三消各自完整播放，冻结窗口覆盖至较晚一组结束，补位一次性完成。
- **复活花色守恒**：净化消除按花色成组执行（恒为 3 的倍数），不出现槽内余数非 3 倍数的非法态。
- **资源缺失**：空 `assets/` 目录下 MUST 完整可玩（Emoji 卡牌 + 程序化背景 + 程序化 BGM）。
- **`file://` 协议**：双击 `index.html` 必须零 CORS 报错；音频 MUST 走 `HTMLAudioElement`，**严禁 `fetch + decodeAudioData`**。
- **切后台**：`visibilitychange → hidden` 暂停 BGM；恢复可见按开关续播；连击 5 秒窗口以时间戳判定，不因切后台误判续连。
- **`prefers-reduced-motion`**：进场退化为一次性淡入；消除退化为原位闪白 + 直接缩至 0（无跳跃、无 Q 弹缩放），总时长口径不变。

## Requirements *(mandatory)*

### A. 核心循环与判定

- **FR-001 棋盘与卡牌**：系统 MUST 呈现 N×N 棋盘（N ∈ [4,8]，随关卡配置），每张卡牌带花色 `s` 与四向之一的方向 `d ∈ {U,R,D,L}`；方向即唯一出路，玩家 MUST NOT 直接拖拽卡牌。
- **FR-002 顺向飞滑判定**：点击卡牌时，系统 MUST 沿 `d` 方向做**同层射线**检测至棋盘边缘——同层 `z` 前方无阻挡则飞出并进入待消槽；有阻挡则前冲碰撞后弹回原位。**凌空飞越**：射线判定 MUST 按层高比较，`z_target < z_self` 的卡牌不构成阻挡（高层可越过低层头顶）。棱镜 MUST 贯穿全层高。
- **FR-003 受阻反馈**：受阻 MUST 播放原地微震 + 双叩音（FR-036），并清零表现层连击计数。**生命机制已下线**：受阻 MUST NOT 扣减生命、MUST NOT 触发 `lost_lives`；`cfg.lives` 仅作兼容只读值（恒不递减），`cfg.damageOnBlock` 恒为 `false`。
- **FR-004 待消槽**：待消槽 MUST 为**固定 7 格**并位于棋盘上方（FR-033）。飞入卡牌 MUST 与槽内同花色归拢相邻排列；槽满 7 格且未触发三消即判爆槽。
- **FR-005 三消与连击**：槽内同花色凑齐 3 张时 MUST 立即触发合体消除（FR-030）、腾出 3 槽、累加连击并按 `cfg.scoring`（`comboBase` + `comboStep × combo`）计分。
- **FR-006 胜负判定**：**胜利** = 棋盘所有卡牌移入槽且三消清空（棋盘 + 槽全空）；**失败** = 待消槽 7 格爆满未成三（`lost_burst`）或棋盘无可行操作且洗牌无法挽救（`lost_deadlock`，防御性兜底）。
- **FR-007 视图形态**：系统 MUST 提供 9:16 竖屏视图——手机浏览器占满视口，PC 浏览器居中并预留右侧调试面板；全部输入 MUST 统一为 PointerEvents。

### B. 棋盘拓扑与关卡系统

- **FR-008 关卡参数矩阵（72 关）**：系统 MUST 提供 72 关确定性配置，结构与代码一致：

  | 关卡 | 网格 | 花色数 K | 层高 zMax | 卡牌数 | 机关 |
  |---|---|---|---|---|---|
  | L1 | 5×5 | 4 | 0（单层） | 18 | — |
  | L2 | 6×6 | 6 | 1 | 48 | — |
  | L3 | 7×7 | 9 | 1 | 63 | — |
  | L4~L72 | 7×7 / 8×8 | 10~24 | 1~4 | 60~141 | 见下行档位 |

  - **波浪骨架**：L4~L72 按 3 关一循环「2 简 1 难」递进，挑战位 = `(id-4)%3==2` 的 **8×8 关（共 23 关）**，其余为 7×7 爽快关。
  - **花色梯度**：L1=4 / L2=6 / L3=9 / L4~L12 递增至 14 / L13~L36 至 18 / L37~L72 至 24。
  - **机关档位**：齿轮 L7 起 / 冰封 L12 起 / 钥匙+锁链 L22 起 / 棱镜 L39 起（首现于 L39/45/56/63/69）。
  - **三大生态阶段**：L1~L24 / L25~L48 / L49~L72，每阶段恰好覆盖 2 幅画卷。
  - 关卡总数 MUST 恒为 72，MUST NOT 回退为 50/60 口径。
- **FR-009 奇偶层半格错位拓扑**：棋盘 MUST 采用奇偶层半格错位堆叠——偶数层（`z = 0,2,4`）位于标准格 `(r,c)`，奇数层（`z = 1,3`）位于 `(r+0.5, c+0.5)`（压在下层 2×2 四格十字交界中心）；同层相邻卡牌间距 `gap = 1px`，方向箭头内嵌于圆角边缘内侧且不被邻牌遮挡。
- **FR-010 压制锁定与零悬空**：任何 `z > 0` 的卡牌，其下方 `z-1` 层支撑象限 MUST 存在有效卡牌（严禁悬空，Generator MUST 拒绝违规候选）。若某卡牌上方 `z+1` 层压角位存在未移除卡牌，则该卡牌处于**被压锁定态**：MUST 不可点击，并 MUST 原位叠加 `rgba(15, 23, 42, 0.28)` 变暗层（零偏移绘制，MUST NOT 另算坐标）；压住它的所有上层卡牌移除后恢复亮白与可点击。
- **FR-011 图形掩码成型**：每关底层与上层 MUST 各绑定一套 36 套图形掩码模板之一（`cfg.maskBase` / `cfg.maskUpper`，落库可查），MUST NOT 回退为正方形满铺；掩码覆盖率为网格的 60%~90%，随层高自然向内收拢以保证零悬空。
- **FR-012 迎头死锁零容忍与运行期自愈**：静态生成 MUST 保证同层同行 `R↔L` / 同列 `D↔U` 迎头死锁对计数为 0；`RulesEngine` 每次操作（含齿轮旋转、洗牌、自愈）后 MUST 执行自愈，使全盘可飞出卡牌数 ≥1（单次操作旋转 ≤4 次，超限走乾坤洗牌兜底，MUST NOT 直接判负）；自愈结果 MUST 进入 Undo 快照且不破坏花色守恒。
- **FR-013 离线流水线**：关卡数据 MUST 由离线流水线生产——逆向生成器（从清空状态反向推入三消组）构建候选 → 自动求解器回溯验证 → 导出纯静态配置文件；前端运行时 MUST NOT 执行关卡生成逻辑（唯一例外：Hint / 自动演示的有界轻量搜索）。
- **FR-014 可解性与难度指标**：每一关 MUST 100% 存在至少一条必胜路径（7 格槽位限制下）；每关 MUST 附带量化难度指标：最优解步数、解路径数、槽位压力峰值、启用机制数、难度评估分，以及空间聚散度（三连簇数 / 双连坐占比 / 完全分散占比）与瓶颈节奏（咽喉点数 / 最小可行操作集 / 最长连锁爽消段）。
- **FR-015 门禁一致性**：关卡数据任何变更 MUST 触发 Solver 全量重验证并更新 `tools/solver-report.json`（交付 72/72 可解）；前端死局判定口径与求解器口径 MUST 一致——**玩家实际可玩局面集合 = 求解器验证过的可解局面集合**。灵犀三消与乾坤洗牌 MUST NOT 进入 `RulesEngine` 常规 tap 判定或 Solver 动作集。

### C. 特殊机关

- **FR-016 齿轮转向**：带齿轮标记的卡牌，当**同层十字相邻**卡牌飞出时 MUST 顺时针旋转 90°（`d = (d+1)%4`）并即时可见；对角相邻飞出 MUST NOT 触发。转向载体统一为齿轮卡牌（地面转向垫载体已取消）。
- **FR-017 冰封**：冰封卡牌 MUST 无法被直接点击飞出（即使前方畅通），但 MUST 作为障碍阻挡射线；冰层厚度为正整数（1~3，`x` 字段）。每触发一次三消，场上所有冰封 MUST 各减 1（`iceMode: "triple"` 主口径；`adjacent` 变体为仅十字相邻者减 1），归零解冻。冰层剩余厚度 MUST 在 UI 可见（霜面 + 裂纹线 + 厚度数字）。
- **FR-018 钥匙与锁链**：被锁链锁定的卡牌 MUST 固定原地并阻挡射线，直至对应钥匙卡牌飞出后自动解锁（`cfg.chains` 配对，一钥可配多锁）；配对关系 MUST 在 UI 可辨识（角标/链路提示）。
- **FR-019 棱镜折射**：棋盘边缘或内部 MUST 可设固定棱镜块（不可移走，`/` 与 `\` 两种折射面，贯穿全层高）；卡牌撞上 MUST 不被弹回，而是按反射表折射 90° 续走并从另一侧飞出；单次飞出折射次数上限为 1，Generator MUST 拒绝可形成对射循环的布局。

### D. 道具与调试

- **FR-020 三大道具**：局内道具栏 MUST 恰为三键——**撤销**（整体回滚一步）、**灵犀三消**（无视方向阻挡与压制锁定强制完成一次同花色三消，优先取槽内已有花色与同花色最顶层卡牌）、**乾坤洗牌**（重排花色与朝向，保证洗后仍可解、每花色总数仍为 3 的倍数）。滑块流转 MUST 仅限「棋盘 → 待消槽 → 三消」单向守恒，或经撤销整体回滚。
- **FR-021 道具次数与购买**：三道具默认每关各 1 次免费（可被关卡配置覆盖）；用尽后角标 MUST 变为 `💎 50`，点击即扣费并立即生效；余额不足 MUST 拒绝扣费与消耗并给出提示（扣费成功飘 `-50 💎`，不足时按钮轻晃）。
- **FR-022 调试面板**：面板 MUST 支持 1~72 关（`LEVELS.length` 动态）跳关、重置本关、Hint、一键自动演示、显示难度评估分与机制标签、显示当前画卷主题名；Hint 与自动演示 MUST 以**当前棋盘与槽状态**实时搜索（`findBestNextMove(state)`），中途偏离 `solutionMoves` 后仍立即生效（≤2s）；音效复选框勾选态 MUST 与全局 `muted` 严格同向。
- **FR-023 面板响应式**：PC 端 MUST 为右侧 320px 侧栏（默认展开），移动端 MUST 为底部抽屉 + 浮动按钮（默认收起），且不影响正常游玩布局。

### E. 表现层

- **FR-024 卡牌底座与方向角标**：卡牌 MUST 为 1:1 奶油白 3D 圆角正方体（底部厚度阴影 + 纯白高光内倒角），多层堆叠通过向左上微量阶梯偏移与层间阴影呈现空间感。方向标识 MUST 为**单枚锐利宽翼三角箭头**（带白色描边、内嵌朝向边缘内侧）；MUST NOT 出现「胶囊椭圆内含两个小点/小三角」造型（猪鼻子红线），MUST NOT 出现左上角圆圈指示器或覆盖图案的半透明圆圈箭头。机制标记（齿轮/冰封/锁链/钥匙）叠加位置 MUST 与底座兼容且互不遮挡。
- **FR-025 图鉴与图标渲染链**：卡牌图案 MUST 按以下优先级取源——① 逐条目单图 `assets/icons/{suit}.png`（可选覆盖）；② 整图切片（主来源）`assets/icons/sheet{1..6}`：六张 4×4 图集、**16 格全部有效（共 96 格）**，映射 `sheetIndex = floor(suit/16) + 1`、`cellIndex = suit % 16`，切出 `256×256` 离屏切片；③ 原生全彩 Emoji 直渲染兜底（`ctx.font` + `ctx.fillText`）。**严禁 `ctx.arc` 手绘圆球加黑点**。`sheet{1..6}` 与 `bg{1..6}` MUST 自动兼容 `.png` / `.jpg` / `.jpeg` / `.webp`（按序探测、命中即缓存、失败静默）。同一 suit 在同一关卡内 MUST 恒映射同一图案；三消判定、Solver 与死局判定 MUST 100% 以 suit 整数值为准。**花色 → 图鉴映射**：关卡内的 `s ∈ [0, K-1]` MUST 经 `mapSuits(levelId, suits)` 映射到**当前画卷的累计图鉴池**（池上限按画卷 `15/30/45/60/75/96`），映射 MUST 为确定性洗牌（种子 = `levelId`，同关可复现、跨关渐进解锁），MUST NOT 依赖 `Math.random()`；`levels.js` 的 `s` 字段 MUST NOT 因图鉴扩容而改写。
- **FR-026 图标归一化（96 条）**：切片 MUST 满足——① 切图内缩 `9%`、运行期兜底内缩 `0.4%`（≈2px）；② 非白阈值 `215`、四周外扩 `6px`，按**非白像素质心**把主体强制对齐到画布中心 `(128,128)`；③ 主体长边占切片画布 `92%`，绘制时以 `tileSize × 0.93` 输出，使主体长边约占卡面 **86%**、四周各留约 `7%`；④ 96 条离线包围盒 `STM_ICON_BBOXES` MUST 为正方形（`size = max(bw,bh)`，按中心扩张后夹回本格），扫描口径为「只忽略最外圈 2px + 非白阈值 246 + 外扩 8px + 连通域 <3px 噪点剔除」；⑤ 96 个切片的不透明包围盒 MUST NOT 触到画布任一边界（零裁切），`node tools/icon-bbox-audit.js` MUST exit 0（含「强墨迹覆盖率 ≥99.5%」与「可见主体占框比 ≥90%」两组门禁）；⑥ 白键控成功时 MUST NOT 再施加圆角遮罩。
- **FR-027 生态背景**：背景 MUST 为 6 幅与画卷严格对应的生态风景大图，画卷序号 = `floor((id-1)/12) + 1`（L1-12 / L13-24 / L25-36 / L37-48 / L49-60 / L61-72），同一画卷 12 关共享同一景；贴图优先 `assets/bg/bg{1..6}`，缺失时 MUST 降级为 Canvas/SVG 程序化风景（逐幅独立判定、会话内缓存不闪烁）。背景层与棋盘层之间 MUST 设半透明蒙版保证对比度。**切片同源铁律**：大厅星盘与结算层的 2×2 晶片 MUST 取自同一文件、同一加载缓存链路，确保「局内所见背景 = 星盘晶片拼出的大图」；未点亮晶片 MUST NOT 泄漏未解锁画面。
- **FR-028 进场编舞（唯一模式：垂直雨幕下落 + 微弹定格）**：每次开局（进入关卡或重置）MUST 播放**垂直雨幕落子（Vertical Rain Drop）**。全游戏只有这一种主模式，另允许一个**只改时序波前**的辐射变体（见下）。横向乱窜、斜向轨迹、旋转/倾斜、缩放弹入与超调放大 MUST 全部废除。
  - **轴向与角度**：每张卡牌的起始位置 MUST 位于其**最终渲染实坐标的正上方**（含奇数层 `+0.5` 偏移后的坐标）；全程水平分量 `|dx| = 0`（容差 ≤0.5px）；角度恒 `0°`——MUST NOT 旋转、MUST NOT 倾斜、MUST NOT 出现斜向或跨屏位移。**统一落距** `FALL_H ∈ [2.6, 3.4]` 卡面边长（设计 `3.0`）：全盘所有卡牌 MUST 取同一落距，MUST NOT 按行 / 按层递减；`FALL_H` 的构造性下限为「**首排**（`r = 0`）起始牌心 MUST 高于 `#dock` 上沿」（判据：起始帧牌心 `y ≤ #dock.getBoundingClientRect().top`，容差 ≤1px），落距不足时 MUST 上提至刚好越界（上限 `6.0` 卡面边长）。旧口径（`0.7~1.4` 短距离空降、首排收缩 `min(FALL_H, r × 格宽 + 0.5 × 卡面边长)`）MUST NOT 复活。
  - **速度曲线**：垂直下落 MUST 为**单峰速度曲线**（下述进度均指**下落段**进度，下落段止于 `IMPACT_AT`）——速度峰值落在 `25%~45%`，峰值 ≥ 平均速度 `1.3×`，触底前一帧速度 ≤ 峰值的 `15%`（先重力加速、末段强刹）；末段 `10%` 时长内位移 ≤ 总落距的 `3%`。下落段 MUST NOT 使用 `back` / `elastic` 一类往返缓动（微弹由独立的挤压段承担，MUST NOT 与下落曲线混写）。
  - **微弹定格**：触底瞬间 MUST 产生 `4~6px` 的**垂直挤压**（`sy = 1 − squash / 卡面边长`，`sx` 反向补偿 ≤ `+1.5%`）；挤压期**底边 MUST 贴地不动**（牌心随压缩**下移** `squash/2`，MUST NOT 出现整牌平移——底边与牌心的相对距离必须改变）；随后 MUST 回弹至 `sy = 1.00`（允许 ≤`1.5%` 的单次超调，且 MUST 在 ≤2 帧内收敛回 `1.00`），再**干脆锁死**——MUST NOT 二次弹跳、MUST NOT 锁死后缩放偏离 `1.00`、MUST NOT 锁死后残余位移。落定帧 MUST 与静态帧逐像素一致。
  - **单卡时长**：`TILE ∈ [180, 220]ms`（设计 `200`）。
  - **触底时刻**：`IMPACT_AT ∈ [0.75, 0.82]`（`TILE` 的归一化进度）为挤压起点，MUST 与 FR-036 的落牌涟漪同源。
  - **时序**：`delay = r × ROW_STEP + c × COL_STEP + z × Z_STEP`（`r`/`c` 取 `Math.floor` 归一后的逻辑整数格——奇数层 `+0.5` MUST 先归一，MUST NOT 直接相加）。
    - `ROW_STEP` 由预算反算，`∈ [16, 64]ms`；`COL_STEP ∈ [3, 8]ms`（只做「轻微对角」）；`Z_STEP ∈ [4, 8]ms` 且恒正（同坐标先底后上）。
    - **预算冲突优先级**：当「总时长落 `380~420ms`」与「首末排起跑差 ≥`150ms`」不能同时满足时（`n = 8` / `zMax = 4` 为最紧档），MUST 先把 `COL_STEP` / `Z_STEP` 压到窗口下限（`3` / `4`）再反算 `ROW_STEP`；MUST NOT 用放大 `COL_STEP` / `Z_STEP` 的方式挤掉行波间距。
    - 推进 MUST 沿 `r` 单调不减（自上而下），同排内沿 `c` 单调不减；同排相邻牌起跑差 MUST ≤ `8ms`（否则读作「逐张排队」）；首排与末排起跑差 MUST ≥ `150ms`（否则读作「整盘同时砸下」）。
  - **总时长**：`total = maxDelay + TILE`，`TARGET = 400ms`，实测 MUST 落 `380~420ms`；跨盘面（`n = 5~8` / `zMax = 0~4`）极差 ≤ `25ms`；MUST NOT 随牌数增长（30 张与 141 张同档）。
  - **辐射变体（唯一合法变体）**：仅允许把**时序波前**由「自上而下」换为「由中心向外逐层」——`delay` 按到盘面几何中心的曼哈顿距离升序、同距离同起。变体 MUST 由关卡静态配置**确定性**选取（MUST NOT `Math.random()`），同关重开恒同一变体；MUST NOT 改变位移轴向（`dx` 仍恒 `0`）、MUST NOT 引入旋转/倾斜、MUST NOT 改变 `TILE` 与总时长窗口。
  - **不透明度（常规模式）**：全程 `alpha` 恒 `1.0`（MUST NOT 淡入）；MUST NOT 用 `ctx.filter` / 运动模糊 / 半透明叠影；同一卡牌同一帧 MUST 只绘制一次。
  - **帧闸门（计时起点 MUST 绑定「玩家真实可见的首帧」）**：`t0` MUST 同时满足下列四项后记录，缺一不可——
    - **(a) 初始化就绪**：关卡数据构建 + DOM 切换 + 贴图预热 + 布局探测 + 音频上下文预热全部完成；
    - **(b) 遮挡解除**：`#modal-root` / `#lobby` / `#splash-screen` / 结算层 / 失败层全部处于不可见态（`hidden` 或 `display: none` 或计算 `opacity ≤ 0.02`），且棋盘画布 `getBoundingClientRect()` 宽高均 `> 0`；
    - **(c) 页面可见**：`document.visibilityState === 'visible'`；
    - **(d) 真实绘制**：在 (b)(c) 同时成立之后，已**真正画完** ≥`2` 个 rAF 帧（`draw()` 抛异常那帧 MUST NOT 计数）。

### F. 声学

- **FR-035 混合双轨声学架构**：
  - **资产轨**：`assets/audio/` 8 个文件（`bgm_lobby` / `bgm_game` / `sfx_shatter` / `sfx_win` / `sfx_lose` / `sfx_voice_good` / `sfx_voice_great` / `sfx_voice_unbelievable`）MUST 经 `HTMLAudioElement`（`new Audio(src)` + `preload="auto"`）加载与播放；**MUST NOT 使用 `fetch + decodeAudioData`**（`file://` 下 `Origin: null` 必报 CORS）。每个音效 MUST 具备独立实例池，高频连击可叠放、互不掐头。
  - **合成轨**：交互级音效（提牌 / 落槽 / 双叩 / 落牌涟漪）与开机和弦 MUST 由 `AudioContext` 实时合成，零文件依赖。
  - 两轨 MUST 共用同一静音开关与主音量通道；单文件缺失/解码失败 MUST 静默降级（BGM 回退 FR-038 程序化合成），MUST NOT 抛错阻塞主循环。
  - **响度基线**：8 个素材 MUST 经 `tools/normalize-audio.js` 归一（BGM `−18 LUFS` / 事件音效 `−14 LUFS` / 语音 `−13 LUFS`，TP 统一 `≤ −1.5 dBTP`），`--check` MUST exit 0；出声电平 = 素材 `I` + `20·log10(volume)`；混音层级 MUST 满足「语音 > 碎裂 > 通关 > 失败 > 局内 BGM / 大厅 BGM」且音效高出 BGM ≥8 dB。
  - **BGM 时序**：`bgm_lobby` 音量 `0.45`、`bgm_game` `0.38`（归一后仅表达约 1.5 dB 设计差）；首次用户交互后起播（首次交互前 MUST NOT 发声）；进关时 `bgm_lobby` 350ms 内淡出、`bgm_game` 同步淡入；返回大厅/结算反向切换；被 autoplay 策略暂停后任意一次 `pointerdown`/`click`/`keydown` MUST 立即恢复（幂等，播放中为零开销空操作）；淡入淡出 MUST 为音量渐变，MUST NOT 硬切。
  - **事件音效**：`sfx_win` MUST 在最后一组三消后延迟 `250ms` 触发并同时把 `bgm_game` 压低 50%；`sfx_lose` MUST 在爆槽/失败弹窗瞬间触发；`sfx_shatter` MUST 每次三消 0ms 瞬发并按 FR-037 升调；同一事件音效同时只保留一个活跃实例。
  - **音频上下文预热**：`new AudioContext()` MUST 在 `boot()` 后首个宏任务建好（`sound.warmup()`），MUST 早于 `startDeal()`，MUST NOT 落在首次落牌上；建出后 `ctx.state` MUST 为 `suspended`（首次手势由 `unlock()` 的 `resume()` 唤醒）；MUST NOT 改用 `requestIdleCallback`（触发点会漂到 1.5~2.1s）。
- **FR-036 交互音（物理碰撞口径）**：交互音 MUST 为「极短瞬态 + 温润短共鸣」的物理碰撞听感，**MUST NOT 做大幅度扫频或长拖尾**（`STM.AUDIO_CONFIG.tap` / `knock` 为唯一参数源）：
  - **提牌（`tap`）**：0ms 高频脆响噪声（`2400Hz` 带通、`Q=3.5`、`12ms`、2ms 内达峰）+ 瓷木共鸣（`520→580Hz`、`28ms` 内微升、`45ms` 衰减）；**落槽（同属 `tap`）**：`115ms` 后 `380→290Hz` / `32ms` 轻叩 + `8ms` 噪声。MUST 在 `pointerdown` 判定合法后同帧起音。
  - **受阻（`knock`）**：原地「哒-哒」双叩，单次 ≤`28ms`、间隔 `55ms`、`310Hz`/`260Hz` 两声、微降 `0.85×`、`8ms` 冲击噪声（占比 0.35）；MUST 与微震同步，听感与提牌一「开」一「合」可盲听区分。
  - **落牌涟漪**：每张卡牌**触底** MUST 触发极短木质/骨牌微触（单声 `15~22ms`、3ms 起音 + 指数衰减、`320→180Hz` 下沉、`800Hz` 低通 `Q=0.7`、单振荡器零泛音）；节流间隔 MUST `≥45ms`，使满载（141 张）整场只余 **8~12 声**「群响」；音高 MUST 随落牌进度由高到低收敛且相邻两声间隔 ≥`45ms`（MUST NOT 构成可辨音阶）；MUST 与 FR-028 的 `IMPACT_AT` 同源，同帧多牌先排序再发声。**红线**：编舞期间 MUST NOT 出现任何 `>60ms` 的持续音、扫频拖尾或电子音床——落子声只作「点缀」。
  - **唯一音源**：交互音 MUST 只有 `tap`（提牌 + 落槽）与 `knock`（受阻双叩）两个口径，且 MUST NOT 被任何机制音覆盖或抢占（FR-049）。
  - **冰封解冻**：MUST 为低域正弦水滴（`480→620Hz` / `70ms` / 峰值 0.22，叠 `320→380Hz` / `50ms` / 0.10），MUST NOT 含 `sawtooth`/`square` 波或 `>1000Hz` 高频成分；`noise()` 原语 MUST 带 ≥6ms 线性起音。
- **FR-037 5 秒滑动窗连击夸赞**：每次三消距上次 ≤`5000ms` 则 `comboCount += 1`，否则重置为 1；无论续连与否 MUST 刷新计时器。分级 MUST 严格如下：

  | Combo | `sfx_shatter` 速率 | 语音（延迟 120ms） | 飘字 |
  |---|---|---|---|
  | 1 | 1.00 | 无 | 无 |
  | 2 | 1.06 | `sfx_voice_good` | `Combo ×2` |
  | 3 | 1.12 | `sfx_voice_great` | `Good! ×3` |
  | 4 | 1.18 | `voice_excellent`（暂无独立资产 → 复用 `sfx_voice_great` 变调 `1.14`） | `Great! ×4` |
  | ≥5 | 1.25 | `sfx_voice_unbelievable` | `Unbelievable! ×N` |

  - **阶梯晋级必响（Δ31 修订）**：档位严格上升时语音 MUST NOT 被任何冷却丢弃。上一句已播完则立即起播；仍在播则最多等 `800ms` 后强发，等待上限 `2000ms` 兜底。MUST NOT 使用跨档的固定长冷却（旧 `3.5s` 硬冷却会吞掉中段档位，导致 `Good → Unbelievable` 跳阶）。
  - **同档防复读**：同一档位在一次连击周期（5 秒滑动窗未中断）内 MUST 只播报一次；`Combo 6/7/8…` 持续处于最高档时 MUST NOT 重复播报 `sfx_voice_unbelievable`，但连击计数、升调与飘字 MUST 正常累加。仅当窗口超时连击归零后，重新打出高连击才允许再次播报。
  - 升调 MUST 用 `preservesPitch = false` + `playbackRate`；`Combo 1` MUST NOT 播语音、MUST NOT 飘字；计时 MUST 以时间戳差值判定（MUST NOT 依赖帧计数，切后台 10 秒返回不误判）。
  - **口径分离**：本条 `comboCount` 为纯表现层（5 秒窗口）；FR-033 的 IQ 乘区为受阻断连（无时间窗）。二者 MUST NOT 互相覆盖或隐式同步。
  - 连击仅驱动音效与飘字，MUST NOT 改写 FR-005 计分、MUST NOT 进入 `RulesEngine` 或 Solver 动作集。
- **FR-038 程序化 BGM 与静音联动**：`bgm_*.mp3` 缺失/解码失败时 MUST 回退 Web Audio 程序化治愈系 BGM（C 大调五声音阶 C-D-E-G-A 的柔和木琴 + 和弦循环），保证空 `assets/audio/` 形态下仍有 BGM。BGM 与音效 MUST 受开关控制（MUST NOT 出现「关掉音效但 BGM 仍响」）；`visibilitychange → hidden` MUST 暂停/静音 BGM，恢复可见按开关续播；BGM 为纯表现层，MUST NOT 影响逻辑与持久化。
- **FR-049 点击链路音效唯一性（机制音 MUST NOT 抢占交互音）**〔编号取未占用的最大号，按主题归入本节 §F〕：一次合法 `pointerdown` 所派生的**全部事件**（`flyout` / `blocked` / 同一次点击级联出的 `gear` / `unlock` / `ice` / `prism` / `comboChanged`）构成「点击链路」。缺陷现状：右上角机关角标（深色圆底 + 金色多角星芒）的卡牌及其**十字邻牌**被点击时，齿轮联动事件会额外起一声方波扫频音，与 `tap` 重叠并把提牌声盖掉——听感为「奇怪/突兀」。约束：
  - **唯一音源**：点击链路内的交互反馈音 MUST 且仅 MUST 来自 FR-036 的两个口径——合法飞出 = `tap`（提牌 + 落槽），受阻 = `knock`（双叩）。链路内 MUST NOT 出现第二个音源与 `tap` / `knock` 的起音窗（`|Δt| ≤ 60ms`）重叠。
  - **机制事件静音**：`gear`（齿轮转向）/ `unlock`（锁链解锁）/ `prism`（棱镜折射）三个机制事件 MUST NOT 播放任何独立音色（含方波 / 三角 / 正弦的一次性扫频音）。其「发生感」MUST 只由视觉（角标脉冲 / 描边闪光 / 折线光条）与同链路的 `tap` 承担。
  - **保留项**：`ice`（冰封解冻）保留 FR-036 的低域正弦水滴口径——它发生在三消结算之后，不落在点击链路的起音窗内；其参数 MUST NOT 因本条被改写。
  - **退役音色**：源码 MUST NOT 保留任何 `square` / `sawtooth` 的一次性交互音（`click` / `gear` / `unlock` / `prism` / `item` / `botTick` 一类的「滴」声全部下线）；自动演示与调试提示 MUST 静默或复用 `tap`（同参数源），MUST NOT 另起电子提示音。
  - **可盲听性**：普通牌 / 带角标牌 / 角标十字邻牌三类点击的听感 MUST 完全一致（同一 `tap` 参数、零随机分支、零按机制分流）。
  - **响度不抢占**：`tap` 峰值 MUST ≥ 点击链路内任何其他合成音的峰值；同一时刻 MUST NOT 有 ≥2 个 `>60ms` 的持续音叠放。

## Assumptions

- **目标用户**：大赛评委与休闲游戏玩家；游戏去叙事化，无剧情、角色对话与世界观包装（题材仅落地为图案 / 背景 / 音频表现层）。
- **技术栈**：原生 HTML5 + CSS3 + Vanilla JS（经典 script + 单全局 `STM` 命名空间）、零构建链、零运行时第三方依赖；离线工具仅用 Node ≥18 内置模块（Generator / Solver / 门禁脚本，零 npm 依赖）。
- **资产分层**：美术为本地可选增强（`assets/icons/*`、`assets/bg/*`，缺失时 Emoji / 程序化强制双兜底）；音频为「`assets/audio/` 8 轨资产 + Web Audio 实时合成」混合双轨（资产缺失时 BGM 回退合成、音效静默）；字体仅系统 Emoji 字体栈。
- **单机体验**：无账号、无后端、无联网多人；进度以 `localStorage` 本地延续。
- **既定常量**：待消槽 7 格、道具 3 种各 1 次免费、关卡 72 关、图鉴展示池 96 种、棋盘 ≤8×8、花色 K ≤24。生命机制已下线（`lives` 仅兼容只读）。
- **难度指标定义**：「解路径数」= 求解器在限定搜索预算（单关 2M 节点）内找到的必胜路径条数；「难度评估分」为由步数 / 路径数 / 槽位压力 / 机制数派生的确定性标量。
- **闸门口径**：教学卡片与预警横幅的放行 MUST 读 `dealRemainingMs()`（实际剩余时长），MUST NOT 用公式硬算（点击快进会让剩余时长提前归零）。
- **编舞预算**：进场总时长 `380~420ms` 与牌数解耦（30 张与 141 张同档）；变体只在**时序波前**上分支（行波 / 辐射），位移轴向恒为纯垂直（`dx = 0`、角度 `0°`），MUST NOT 因变体引入横向或旋转分量。
- **范围外**：成就、社交分享、商城、真实支付、本地化多语言、排行榜均属赛后 backlog，本期不实现。
- **文档边界**：`plan.md` 只承载「已交付基线 + 下一阶段规划」，`tasks.md` 只承载未决待办，历史任务全部归档于 `tasks-archive.md`；三者不得与本文口径冲突。
