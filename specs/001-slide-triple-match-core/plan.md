## Summary

构建零构建链的纯 Web H5 游戏《Slide & Triple》：9:16 竖屏棋盘上，玩家点击带方向箭头的滑块——射线畅通则飞出棋盘进入 7 格收集槽（Δ19：待消槽移至棋盘**上方**），同花色凑三即消；配合齿轮旋转、冰封、钥匙锁链、棱镜折射四大机制与三大局内道具（撤销 / 灵犀三消 / 乾坤洗牌），由 Node 离线流水线（逆向生成器 + 回溯求解器）量产并 100% 验证 **72 个标准关卡**（Δ13 增量扩容: 原 50 关 100% 保留 + 10 新关拼接；Δ16 尾部扩容: 既有 60 关 100% 保留 + 12 新关追加；Δ15 花色重打散迁移: 同花色空间聚散度三档曲线达标；**Δ19 v2 布局全量受控迁移: 奇偶层半格错位堆叠 + 36 套图形掩码成型 + 「单线咽喉点」瓶颈节奏——既有 72 关全量重塑，Δ13/Δ16 逐字节零改写铁律本轮受控让位、迁移后复位**；可经参数表无缝扩容至 100+），前端运行时零生成逻辑、零强制外部资源（Δ15: 本地可选美术贴图 + Emoji/程序化强制双兜底）、双击 index.html 即可游玩。

技术路径：前端为原生 HTML5 + CSS3 + 经典 `<script defer>` 加载的 ES2020+ 代码（单全局命名空间 `STM`，保证 file:// 协议零跨域报错，见研究决策 D-01）；规则引擎 `src/core/RulesEngine.js` 为前后端共用纯函数模块（游玩与求解口径 100% 一致）；关卡数据为带预计算最优解 `solutionMoves` 的静态 JS 配置数组。实施按 **M1 核心循环 MVP → M2 四大机制与道具（冻结规则引擎）→ M3 离线流水线量产 50→60 关（Δ13 增量扩容）→ M3.5 万物出发表现层（45 种图鉴 / 生态背景 / 激励横幅 / BGM——纯渲染与音频层，Δ14）→ M3.6 空间打散迁移 + 贴图双兜底 + 箭头重做（Δ15）→ M4 调试面板 / Bot / 无缝扩容验证 → M5 商业化外围 UI 闭环与 72 关拼图经济系统（Δ16——开机动画 / 主大厅 / 棱晶经济 / 结算与复活）→ M6 半格错位图形棋盘 + 顶部待消槽 + IQ 指数 + 三大道具 + 白瓷碎裂视听（Δ19——核心玩法布局重构 + 局内 UI 规范，US7）** 「四阶段 + 表现层 + 外围闭环 + 玩法重构」推进（Core-First, Levels-Later, Presentation-Last, Shell-Last, Gameplay-Refactor-Last）。

## Technical Context

**Language/Version**: 浏览器端 JavaScript（ES2020+ 语言特性；classic script 加载，禁用 import/export 语法，见 D-01）；离线工具 Node.js ≥ 18（CommonJS，零 npm 依赖）。

**Primary Dependencies**: 运行时零第三方依赖。仅平台 API：Canvas 2D、Web Audio API、PointerEvents、localStorage、URLSearchParams、structuredClone、document.visibilityState（Δ14 BGM 失焦联动）、HTMLImageElement（Δ15 贴图加载——`Image` 相对路径 + onerror 降级，不引入 fetch/XHR）。离线工具仅用 Node 内置模块（fs / path / process）。

**Storage**: 玩家进度 localStorage（try/catch 防护，见 D-03；Δ16 增补第二键 `slide-triple:profile:v2` 承载经济与档案态——与 v1 进度键并存不迁移）；关卡数据纯静态 `src/data/levels.js`（生成工件，随仓库交付）；验证报告 `tools/solver-report.json`（生成工件）。

**Testing**: 三层、零测试框架（零构建约束，见 D-14）：
1. `node tools/solver.js` — 全量可解性验证 + 数据契约校验，exit code 门禁（FR-030/FR-031）；**Δ19 增补：v2 布局下增列零悬空违规计数与瓶颈节奏指标（咽喉点数 / 最小咽喉点可行操作集 / 最长连锁爽消段）核验**；
2. `node tools/solver.js --engine-selftest` — RulesEngine 规则不变量断言（转向/折射/级联/终局判定；**Δ19 增补：奇偶层半格坐标换算 / 同层射线独立 / 压制锁定 / 零悬空断言组**）；
3. [quickstart.md](quickstart.md) 人工验收场景（按里程碑分档）。

**Target Platform**: Evergreen 桌面/移动浏览器（Chrome / Edge / Firefox / Safari，含 file:// 双击直开）；Windows / macOS / Linux + Node ≥ 18（仅离线工具）。

**Project Type**: 零构建静态 H5 游戏 + Node 离线关卡流水线（Generator / Solver）。

**Performance Goals**: 首屏可交互 < 3 s（SC-003——Δ15 后空 assets 形态 MUST 不劣化，贴图形态允许加载期兜底先渲）；棋盘动效 60 fps（中端手机）；Solver 单关验证预算 2M 节点、全量 72 关 < 6 分钟（离线，Δ16 扩容 60→72）；Hint 有界搜索 ≤ 100k 节点且 < 300 ms；Δ14 表现层预算：45 图案 Sprite 预渲染 + 底座重绘不降帧（棋盘满载 8×8×5 层 105 滑块稳定 60 fps）、背景层每景实例化 ≤16 ms 且低速/静态化、BGM 合成 CPU 占用 < 1%（Web Audio 调度表驱动）；Δ15 增补预算：贴图加载不阻塞首帧（兜底先渲、贴图就绪后惰性换装）、redisperse-60 全量迁移 + 重验证 < 10 分钟（离线一次性）；Δ16 增补预算：开机动画 2.0s 主线程占用 < 8%（纯 CSS transform/opacity + rAF 字母变形，**零布局抖动**）、大厅与弹窗切换 < 100 ms、棱晶星盘 2×2 晶片切片复用已加载背景 Image（**零额外网络/解码开销**，Δ17 换肤零额外开销）、棱晶扣费为同步原子操作（< 1 ms）；**Δ19 增补预算：白瓷碎裂 VFX 峰值 45~60 枚多边形碎片同时在场（每三消一次）须设粒子上限与生命周期上限，8×8×5 层满载关卡棋盘动效仍稳定 60 fps（碎片 MUST NOT 触发 GC 抖动）；半格错位渲染的命中测试 MUST 维持 O(层数) 命中查找而非全盘扫描；migrate-layout-72.js 全量 72 关迁移 + 重验证 < 10 分钟（离线一次性，与 Δ15 同量级）**。

**Constraints**: file:// 协议双击零控制台报错、零跨域；运行时零网络请求、核心代码零强制二进制素材（Δ15/SC-006 重定义——`assets/` 为本地可选增强目录，空目录/缺文件时 Emoji 卡牌 + 程序化背景强制双兜底完整可玩）；PointerEvents 单一输入模型；前端运行时不执行任何关卡生成/全量求解逻辑（仅 M4 Hint 的有界轻量搜索例外，见 D-06）；**Δ19 追加：灵犀三消的「无视阻挡」语义 MUST NOT 进入 RulesEngine 常规 tap 判定或 Solver 动作集，乾坤洗牌亦不入动作集——二者仅为道具层能力，否则将破坏 FR-032（玩家实际可玩局面集合 = 求解器验证过的可解局面集合）**。

**Scale/Scope**: 棋盘 ≤ 8×8、滑块 ≤ 150（Δ11 大棋盘）、花色 ≤ 8、关卡交付 **72**（Δ13 扩容 60 → Δ16 尾部扩容 72; Δ19 v2 布局全量受控迁移，**关卡总数仍为 72、波浪骨架与三大生态阶段区间零改动**; 参数表可扩至 100+）；`levels.js` ≤ 380 KB（Δ13 实测 315 KB @60 关 → Δ16 按 72 关线性外推 ≈375 KB；**Δ19 后因每关增列层数/掩码模板 id 与半格坐标，预算上浮至 ≈430 KB**）。

### 核心架构决策（详见 research.md）

- **D-01 脚本加载**：经典 `<script defer>` + 单全局命名空间 `STM` + 共享文件 UMD 双导出 —— file:// 双击零跨域的必要条件（ES module 的 file:// 加载被 Chrome/Edge/Firefox/Safari 以 CORS 拦截）。
- **D-05 渲染分层**：棋盘单 Canvas 2D（含粒子动效）；HUD / Dock / Staging / 调试面板为 DOM + 内联 SVG。
- **D-06 Hint/Bot**：在轨状态回放预计算解；偏离状态有界 DFS（RulesEngine 同口径）；Bot 兜底重置重放，保证「直至该关胜利」。
- **D-07 Solver 规范化**：dock 顺序不参与状态哈希（tap 结局仅依赖花色计数），搜索空间大幅压缩。
- **D-10 生成器**：逆向构造 → 正向自检 → Solver 门禁三重验证，镜像逻辑错误由验证兜底。
- **D-11 单滑块单机制**：gear XOR ice XOR lock XOR key，规避规则交互矩阵爆炸。
